## 总体架构

### 三层实现模型

30 种能力按对抗强度分布在三个实现层，**优先使用高层，仅在高层无法覆盖时才下沉**：

| 层 | 手段 | 特点 | 典型能力 |
|----|------|------|----------|
| **事件层** | Forge 事件（`LivingHurtEvent`、`PlayerTickEvent` 等） | 兼容性最好，其他模组可感知 | 灵巧、大地之力、伤害抗性 |
| **Mixin 层** | 字节码注入原版方法（`hurt`、`setHealth`、`canBeAffected` 等） | 拦截事件系统覆盖不到的路径 | 净魂、不朽装备、死亡抗拒 |
| **反射直写层** | `HealthUtil` 直接读写 `SynchedEntityData` 内部字段、实体追踪结构 | 对抗其他模组的 Mixin/ASM 拦截，"最终手段" | 影杀、真实血量、破敌之眼兜底 |

设计约定是**事件驱动优先**：能力的业务逻辑尽量放在事件层 Handler 中，Mixin 只做最低层拦截，反射直写只作为被外部模组拦截后的兜底补刀。

### 生效门禁模型

每个能力的效果代码执行前都要通过统一的门禁链：

```
服务端检查（isClientSide 直接 return）
  -> isAdventurer() 或 isFullyUnlocked()   佩戴冒险饰品激活的身份
  -> isAbilityEnabled("<id>")              玩家可在能力面板（P 键）自由开关
  -> （部分能力）isFullyUnlocked()          觉醒专属门禁
```

> **v1.2.7 重构**：门禁链统一封装到 `AbilityGate.isAbilityActive(player, id)`，需要 progress 对象时用 `getActiveProgress(player, id)`（避免 `isAbilityActive` + 再查一次的双重查询）。各 Handler 不再重复写 `getAdventureProgress -> isAdventurer||isFullyUnlocked -> isAbilityEnabled` 三连。百分比觉醒倍率统一走 `AbilityGate.awakenedRatio`（value/100，cap 0.95）/ `awakenedPercent`（不除 100，cap 参数）。
>
> **v1.3.1 补充**：① `AbilityGate.isActive(progress, id)` 一行断言收敛「冒险者/觉醒 + 能力启用」双行样板；`AbilityGate.value(progress, id)` 返回 `Optional<Float>`（能力未注册 = empty，与「null 不处理」语义完全等价）；② 能力 ID 字面量统一收敛到 `util/AbilityIds` 常量类（typo 编译期可查）；③ 高频 Mixin 注入点（`getHealth` / `getAttribute` / `setHealth`）经 `util/ProgressCache` 按 tick 缓存 progress 引用（弱 key 防泄漏；缓存的是引用而非门禁结果，能力开关/解锁/觉醒同 tick 即时生效，无延迟）。

**门禁与觉醒的关系（v1.2.1 修正）**：所有能力**统一遵循里程碑制**--所属里程碑解锁后即可使用，`isAbilityEnabled(id)` 内部会做里程碑归属校验。以下能力曾遗留 `isFullyUnlocked()` 硬门禁（未觉醒即使已解锁也不生效），v1.2.1 已统一改为 `isAdventurer() || isFullyUnlocked()` 组合门禁：

- 受击坚韧 `resilience`（里程碑 8 解锁）
- 死亡抗拒 `death_defy`（v1.3.0 起归属里程碑 7）
- 真实血量 `true_health` / 拒绝篡改 `reject_manip` / 旅者之力 `active_skill`（里程碑 10 解锁）

觉醒（`isFullyUnlocked()`）不再是这些能力的**准入门禁**，仅作为数值/机制强化层--例如受击坚韧觉醒 +6 层上限、死亡抗拒觉醒时联动免费审判、拒绝篡改觉醒 30% 反弹等，都在各 Handler 现有门禁通过后追加。

**v1.2.5 门禁两处加固**：
- **`adventurer` 不变式**：`activateFullyUnlocked()` 现连带置 `adventurer = true`（全解锁蕴含冒险者）；`checkAndActivateAdventurer()` 检测到 `fullyUnlocked = true` 但 `adventurer = false`（版本飞升 / 旧存档数据不一致）时自动补激活。由此 `isFullyUnlocked()` 为 true 时 `isAdventurer()` 必然也为 true，组合门禁 `!isAdventurer() && !isFullyUnlocked()` 两分支互为兜底。
- **攻击方能力 `receiveCanceled = true`**：淬魂 / 影杀 / 禁疗 / 破敌觉醒等攻击方能力的事件监听改用 `@SubscribeEvent(receiveCanceled = true)`，**不再检查 `event.isCanceled()`**--当亚波伦等模组在 `LivingHurtEvent` 取消伤害时，这些能力仍正常执行。仅受伤方能力（伤害抗性）保留 `isCanceled()` 门禁。同时新增 `rawAttacker` 回溯：`source.getEntity()` 非 Player 时依次尝试 `getDirectEntity()`、投射物 owner，兼容拔刀剑 / 投射物 `causingEntity` 缺失的场景。
  > **v1.3.4 更正**：攻击方能力**恢复 `event.isCanceled()` 检查**（淬魂/影杀/禁疗/破敌觉醒分支在追溯攻击者后显式检查）——"被取消仍强行结算"的职责改由破敌之眼穿透覆盖（手动 post 的事件本身未取消），被其他模组 cancel 的伤害（否定类机制）不再强行结算；`receiveCanceled = true` 的现存作用是保证事件已发计数 `mark`（`PiercingGazeUtil.markVanillaHurtEventPosted`，破敌之眼 Layer 0 补发判定依赖）不因取消而丢失。

### 数值成长公式

有成长的能力，其数值随**已解锁里程碑数**（`count`）线性或步进增长，`countAtUnlock` 为该能力所属里程碑的序号（由 `MilestoneRegistry` 从 milestones.json 加载后动态填充）：

```
线性：value = BASE + PER_MILESTONE × (count - countAtUnlock)      // 灵巧、伤害抗性、加速等
步进：value = BASE + STEP × ((count - countAtUnlock) / 2)         // 鸿运当头、休养生息等（每 2 里程碑一档）
固定：value = -1                                                   // 解锁即完整（灵魂绑定、净魂、不朽装备等）
```

> **v1.2.7 重构**：成长公式封装到基类--线性能力继承 `LinearGrowthAbility`（实现 `base()` / `perMilestone()` 从 `ModConfig` 取值）、步进能力继承 `StepGrowthAbility`（实现 `base()` / `step()`，默认 divisor=2）、无成长能力继承 `AbstractAbility` 用默认 `value() = -1`。`countAtUnlock` 字段与 setter 由 `AbstractAbility` 统一封装，子类构造传初始值（兜底，实际由 `MilestoneRegistry` 加载 JSON 后覆盖）。
>
> **v1.3.1 下限保护**：公式中 `count - countAtUnlock` 统一 `Math.max(0, ...)`——设计允许任意顺序解锁，跳序解锁时差值为负会产生反向效果（如坚韧之躯裁剪最大生命、鸿运当头扣附魔等级）。顺序解锁数值完全不变。
>
> **v1.3.2 指令后门平移**：数据包 `disabled_abilities` 黑名单中的能力可被指令（`/ap unlock ability`，per-player）解锁。此类能力不经过里程碑，数值经 `AbilityGate.effectiveCount(progress, id)` 平移（`count - grantedAt + countAtUnlock`，下限 0）：解锁时刻的已解锁里程碑数为 `grantedAt`，解锁瞬间数值 = 基础值，之后每解锁一个里程碑正常吃成长——**对线性/阶梯/档位公式均成立**（档位判断平移后等价于"解锁后第 N 个里程碑"）。

各能力成长类型与 `countAtUnlock`（= 所属里程碑序号，由 `MilestoneRegistry` 动态填充）一览：

| 成长类型 | 能力（countAtUnlock） |
|----------|----------------------|
| **线性**（`LinearGrowthAbility`） | 灵巧(1)、大地之力(1)、不动如山(3)、加速(3)、无形之手(4)、磁吸(4)、经验加成(5)、嗜血(6)、伤害抗性(6)、禁疗之触(7)、坚韧之躯(7) |
| **步进**（`StepGrowthAbility`，divisor=2，每 2 里程碑一档） | 休养生息(2)、鸿运当头(5) |
| **无成长**（`AbstractAbility`，value 固定 -1） | 虚空踏步(2)、灵魂绑定(3)、全视之眼(4)、不朽装备(5)、环境免疫(6)、死亡抗拒(7)、净魂(8)、满载而归(8)、翱翔(9)、淬魂之力(9)、破敌之眼(9)、恩赐永驻(9)、影杀(10)、真实血量(10)、拒绝篡改(10)、旅者之力(10) |
| **特殊** | 受击坚韧(8)：自实现 `value(int count)` 三档 5/8/12 层（配置 `resilience_stacks_8/9/10`），另有觉醒重载 `value(count, awakened)` |

> 注：禁疗之触/坚韧之躯虽为线性基类，但数值直接进效果时长/属性，不经过成长公式以外的转换；坚韧之躯觉醒用 `Math.ceil` 而非浮点乘法（见下文）。
>
> 注：虚空踏步(2)/死亡抗拒(7)/影杀(10) 虽列"无成长"，但重写了 `value()` 返回各自配置固定值（跳跃倍率/无敌与冷却时长/影杀固伤基值，供面板展示）——同样不随里程碑成长，非恒 -1。

### 觉醒机制（第 11 阶段）

全部里程碑达成并持有「冒险的终点」后 `isFullyUnlocked()` 为 true，各 Handler 在门禁后追加觉醒分支：

- **数值强化**：数值 × `AWAKEN_MULTIPLIER`（默认 1.5），部分带硬上限钳制（`awaken_percent_cap`，默认 0.95）
- **机制质变**：新增行为（御风冲刺、AOE 斩杀、免费审判、过量吸血转护盾、威胁雷达、御风联动移速等），使用各自独立的觉醒配置项
- 全部 30 种能力在觉醒阶段均获得强化（机制质变或数值强化）

觉醒强化类型速查（30 种能力全部有觉醒）：

| 类型 | 能力 |
|------|------|
| **×`AWAKEN_MULTIPLIER`（1.5）** | 灵巧（钳 0.95）、大地之力（另 + 无视水中/空中惩罚）、不动如山（钳 100%）、无形之手、经验加成（×`awaken_xp_boost_mult`）、伤害抗性（钳 0.95）、加速（移速部分，另 + 疾跑推开） |
| **独立配置数值** | 休养生息（+5 HP）、磁吸（半径 ×1.5 + 吸经验球）、不朽装备（护甲 +2 / 武器 +25%）、鸿运当头（+2 等级）、禁疗之触（+ 易伤 ×1.2）、坚韧之躯（×1.5 向上取整）、受击坚韧（+6 层）、满载而归（取最大数量 + 每样 2 份）、翱翔（飞行速度 ×1.5）、淬魂之力（≤20% 斩杀 ×2.0）、拒绝篡改（30% 反弹）、旅者之力（审判范围 ×1.5 / 庇护可移动 30%） |
| **纯机制质变** | 虚空踏步（御风冲刺）、灵魂绑定（保经验）、全视之眼（威胁雷达）、环境免疫（免疫一切无实体来源伤害）、嗜血（过量吸血转护盾）、死亡抗拒（免费审判）、净魂（虚弱光环）、破敌之眼（禁无敌帧 3 秒）、恩赐永驻（正面无法驱散）、影杀（AOE 斩杀链）、真实血量（防秒杀底线 1 HP） |

## 共享基础设施

多个能力共用以下工具类，后文不再重复展开。

> **配置 TOML 定位**：所有配置键位于 `冒险能力配置 > 能力数值 > <能力名>` 子分组（每个能力一个子分组，如「灵巧」「伤害抗性」），觉醒相关键统一在 `冒险能力配置 > 能力数值 > 觉醒强化` 分组，调试相关键（`debug_log` 总开关 + 7 个能力子开关，v1.3.6）在 `冒险能力配置 > 调试` 分组。各能力章节「配置：」行只列键名，未列分组前缀；`ModConfig.java` 中字段名即 TOML 键名（`AGILITY_BASE` → `agility_base`）。

### HealthUtil - 血量反射工具（`util/HealthUtil.java`）

对抗外部模组篡改血量的核心武器库。原理：原版血量存储在 `SynchedEntityData`（实体同步数据）中，`getHealth()`/`setHealth()` 只是访问器--外部模组常用 Mixin/ASM 拦截访问器，但很难拦截对底层数据结构的直接读写。

| 方法 | 用途 |
|------|------|
| `getHealthDirect()` | 反射拿 `DATA_HEALTH_ID`（SRG `f_20961_`）直接从 `SynchedEntityData` 读真实血量，绕过 `getHealth()` 覆写 |
| `getEffectiveHealth()` | **架空参照读数（v1.3.4 新增，见 v1.3.4 条目）**：`|getHealth() - getHealthDirect()| > 1.0` 判定原版血条被架空（重写 getHealth 走自定义槽的 Boss）时取 `getHealth()`（真实血量），否则回落 DataItem 值（防 ASM 篡改 getHealth）。攻击侧血量基准/扣血检测统一入口（玩家侧防御仍用 getHealthDirect 防 ASM） |
| `setHealthDirect()` | 同理直接写入，绕过 `setHealth()` 覆写 |
| `setAllHealthLikeDirect()` | 写原版血量 + 通过 `scanCustomHealthKeys()` 扫描实体类继承链上所有 `EntityDataAccessor<Float>` 字段（带缓存），把自定义血量条目一并写入--对付把血存在自定义字段里的 Boss。**v1.2.5 两处增强**：① **参照血量选择**--`getHealth()` 与 `getHealthDirect()` 差 >1.0 时判定原版血条被架空（亚波伦等 Boss 重写 `getHealth()` 返回真实血量），改用 `getHealth()` 作参照，否则扫不到差距过大的自定义血量；② **值范围约束**--Float 值需落在参照血量 10% 容差内（或差 ≤1.0）才认定为自定义血量 key，排除史维特 `DATA_WATER_DAMAGE_SCALE` 等非血量 Float 误写（曾导致 `onSyncedDataUpdated -> Slime.move` 卡死） |
| `setAllHealthLikeRaw()` | 三步饱和写入：快照当前血量 -> `setAllHealthLikeDirect` -> 遍历 `SynchedEntityData.itemsById` 的所有 `DataItem`，对值≈快照值的条目**直接写 `DataItem.value` 字段**（支持 Float/Double/Integer），完全不经过 `data.set()`，绕过 dirty 标记、监听器和一切 Mixin |
| `clearNegativeFloatDeltas()` | 把 DataItem 中所有负值 Float 归零。反制某些 Boss 向玩家注入"负血量偏移量"再 ASM 篡改 `getHealth()` 叠加的手法。**仅供 TrueHealth 防御侧调用，攻击侧不用** |
| `restoreFoodData()` | 反射直写 `FoodData.foodLevel`（`f_38696_`）= 20、`saturationLevel`（`f_38697_`）= 20，绕过 `setFoodLevel()` 拦截 |
| `removeDirect()` / `setRemovedDirect()` / `setRemovedFieldDirect()` | 三种强度的实体移除：反射调 `remove()` -> 反射调 private `setRemoved()`（不参与虚分派）-> 直接写 `Entity.removalReason` 字段（`f_146795_`） |
| `clearRemovedFlag()` | 写 `null` 到 `removalReason`，把被外部标记移除的玩家"复活" |
| `eradicateFromWorld()` | 从 Minecraft 内部 7 个实体追踪结构直接抹除实体（详见[影杀](#影杀-shadow_kill)；**v1.3.6 新增第 7 个：龙部件 `dragonParts`**） |
| `setHealthLikeAny()` | **v1.3.5/1.3.6 分级直写统一入口**：① 通用层 `setHealthLikeGeneric`（扫描目标类含 "health" 的 `(float)` setter，调用后验证血量变化闭环）-> ② 插针层 `probeCapabilityHealth` -> ③ `setAllHealthLikeRaw`（DataItem 按值匹配兜底）。淬魂补刀/禁疗钳制/影杀归零 v1.3.5~v1.4.1 走此入口，**v1.4.2 起统一改走 `BloodWriteEngine`（本方法保留为引擎关闭时的兼容路径，见 v1.4.2 条目）** |
| `probeCapabilityHealth()` | **v1.3.5 对象图插针**（详见下方"对象图插针体系"小节）；**v1.3.6 写值前验证**：缓存命中时字段当前值须仍接近真血读数，路径漂移（同类多实例/Collection 索引错位）则缓存作废回退全图重探测（`probeFresh` 抽取）——杜绝盲写错误宿主 |
| `zeroAllSynchedFloats()` | **v1.3.6 全 float 同步保险丝**（砧板之刃[神]同款）：遍历目标所有 `DataItem`，float 类型一律字段直写归零——覆盖"不联动 `getHealth` 的隐藏 float 同步条目"（按值匹配/插针都够不到的旁路）。仅用于必杀场景（影杀饱和式秒杀），目标即将被删除副作用随实体消失；Player 守卫（饱食度/吸收等 float 条目属误伤） |
| `writeRemovalReasonDirect()` | **v1.3.6** `setRemovedFieldDirect` 的泛化版本（参数 `Entity` 而非 `LivingEntity`），供非 LivingEntity（如 `EnderDragonPart`）复用同一字段直写 |

**对象图插针体系（v1.3.5 引入，v1.3.6 补写值前验证）**：通用"找真血"手段——不依赖任何模组 API/包名，纯对象图遍历 + 验证闭环：
- **门禁 `probeDataItemLinked()`**：直写 `DATA_HEALTH_ID` 槽 value = 原值-1（绕过 `set()` 直改 `DataItem.value` 字段），观察 `getHealth()` 是否联动。联动 = 正常实体 -> DataItem 直写足够，跳过插针（性能门禁）；不联动 = `getHealth()` 被重定向/架空（如亚波伦 ASM 改写读 `MegaCapability`）-> 进插针层。扰动同 tick 内 finally 还原，客户端无感知

- **路径缓存 `WritePath`**（v1.3.5）：命中后缓存（字段 + 实体→宿主引用路径链），后续同类实体直写 O(深度) 直达宿主，不再全图搜索（弹幕 Boss 大对象图不卡）；**v1.3.6 写值前验证**：字段当前值仍须接近真血读数，路径漂移则缓存作废、回退全图插针重探测（`probeFresh`）——杜绝盲写错误宿主；`searchByClass`/`searchInstance`（旧按类盲搜兜底）v1.3.6 失去调用方后清理

### InvulClearUtil - 自定义无敌清除

`clearCustomInvulTimers(LivingEntity)` 遍历实体类继承链上的所有字段，按命名模式反射清除模组 Boss 的自定义无敌：

- `int` 字段名含 `invul`/`Invul` -> 置 0（如 Goety 的 `moddedInvul` / `obsidianInvul`）
- `boolean` 字段名含 `invul`/`Invul` -> 置 false
- `boolean` 字段名含 `vulnerable`/`Vulnerable` 且不含 `invul` -> 置 true（如 Mowzie's Mobs 钢铁守护者的 `vulnerable`）

> Java `String.contains()` 大小写敏感，故对每个模式显式覆盖大写开头变体（`Invul` / `Vulnerable`）。

### FriendlyFireProtection - 友伤保护

`isOwnerTarget(attacker, target)`：目标是 `TamableAnimal` 且主人是攻击者本人时返回 true。所有"超模"进攻能力（淬魂、影杀、破敌之眼、审判、嗜血）在生效前都先过这个检查，保证不会误伤自己的狼、猫或其他模组的驯服生物。

### FortuneContext - 跨 Mixin 上下文传递

两个 `ThreadLocal`（`CURRENT_BREAKER` / `AWAKENED`），解决"Mixin 注入点参数里没有玩家引用"的经典问题（详见[鸿运当头](#鸿运当头-fortune_favor)）。

### AbilityGate - 能力门禁与觉醒倍率

`isAbilityActive(player, id)` 封装"冒险者/觉醒 + 能力启用"三连门禁；`getActiveProgress(player, id)` 返回通过门禁的 `IAdventureProgress`（避免 `isAbilityActive` + 再查一次的双重查询）；`isActive(progress, id)` 一行门禁断言（已有 progress 对象时）；`value(progress, id)` 能力数值取值（`Optional<Float>`）；`awakenedRatio` / `awakenedPercent` 统一百分比能力的觉醒倍率计算（含 cap 钳制）；**`effectiveCount(progress, id)`（v1.3.2）**：指令后门（`/ap unlock ability`）解锁的被禁用能力按解锁时刻快照平移的有效里程碑数 `count' = max(0, count - grantedAt + countAtUnlock)`——解锁瞬间数值 = 基础值，之后每解锁一个里程碑正常吃成长，不受原归属里程碑位置限制；**所有能力数值调用点必须经 `effectiveCount` 或 `value` 取数，禁止直接 `ability.value(progress.getUnlockedMilestoneCount())`**。各 Handler 门禁与倍率统一走此类。

### AbilityIds - 能力 ID 常量

30 个能力 ID 的常量集中管理（`AGILITY` / `SHADOW_KILL` 等）。代码侧调用（`isAbilityEnabled` / `AbilityRegistry.get` / `getActiveProgress` / `toggleAbility`）统一引用此类，重命名/纠错可由 IDE 全局重命名，typo 从「运行时静默失效」降为「编译可查」。伤害类型 ID（`soul_strike` / `judgment` / `shadow_kill` 的 damage_type）与能力 ID 同名但语义不同，保持 `DamageUtil` 中的字面量。

### ProgressCache - 高频注入点门禁缓存

`get(entity)` 以实体为弱 key 缓存「本 tick 已解析的 progress 引用」（tick 变化即失效重算），供 `TrueHealthMixin.getHealth` / `RejectHealthManipMixin.getAttribute/setHealth` / `DeathDefyMixin.setHealth` 等 MC 极高频调用点使用——`getHealth` 每 tick 每玩家数十次，每次 `LazyOptional.resolve()` 代价昂贵。缓存的是引用而非门禁结果，`isAdventurer` / `isAbilityEnabled` 每次调用仍实时读内存字段，无延迟；弱 key 保证玩家实体 GC 后条目自动释放。

### PiercingGazeUtil - 破敌之眼穿透结算

`resolveAttacker(source)` 追溯真正攻击者：先取 `source.getEntity()`（MC 语义为责任/间接实体，通常即攻击者）-> 为空再取 `getDirectEntity()`（直接实体）-> 若为 Projectile 再取 owner；`postHurtEvent` 手动 post `LivingHurtEvent` 并取 `max(原值, 事件值)` 防 Boss 限伤；`invokeActuallyHurt` + `afterPierceFallback`（血量直写兜底 + 清自定义无敌字段）三连穿透结算，破敌之眼三层 Mixin 共用。

**事件已发标记（v1.3.3 布尔方案 → v1.3.4 单调递增计数）**：判断"本次 hurt 是否已 post 过 `LivingHurtEvent`"——正常环境原版管线（`ForgeHooks.onLivingHurt`，1.20.1 位于 `actuallyHurt`）或各手动 post 路径已发过，重复补发会让淬魂/嗜血/禁疗等监听器同 tick 双倍结算（影杀已有 `SHADOW_KILL_TICKED` 去重，淬魂/嗜血没有）。**v1.3.3**：`VANILLA_HURT_EVENT_POSTED` `ThreadLocal<Boolean>` + `mark/clear/consume`——mark 单一来源 = `CombatAbilityHandler.onLivingHurt` 监听器入口（任何 post 的事件必然触发监听器，不依赖 Mixin 注入点）；Layer 0 调 `target.hurt()` 前 clear（作用域隔离）、扣血成功后 consume（读后清除）；穿透路径不消费，残留由下次 attack 开头 clear 兜底。**v1.3.4**：布尔升级为**单调递增计数**（`VANILLA_HURT_EVENT_POST_COUNT` `ThreadLocal<Long>` + `markVanillaHurtEventPosted` / `getVanillaHurtEventPostCount` / `beginVanillaHurtScope` / `consumeVanillaHurtEventPosted` / `peekVanillaHurtEventPosted(base)`）——全局布尔无法区分"本层/外层"：嵌套 hurt（Boss 在 hurt 管线内对另一实体 AoE、风暴守卫跳过的递归）时 clear/恢复会污染外层判定（外层误判"未 post"→ 补 post + 再次 actuallyHurt 双倍结算）；计数按"本层开始时的基准"比较增量天然栈式隔离（Layer 0 用 `beginVanillaHurtScope` 记录攻击作用域基线、Layer 2 栈帧记录 `postedBase`），无需压栈恢复（计数单调递增，外层基准始终有效）。放在工具类而非 Mixin 类：@Mixin 类禁止非 private static 方法（Mixin Applicator 会尝试混入目标类导致 InvalidMixinException）。

## 里程碑 1 · 初次夜冕

### 灵巧 `agility`

**效果**：受到任何伤害时有概率完全闪避（伤害归零，不触发后续减伤链）。闪避率 10% -> 73%（随里程碑成长），觉醒后 ×1.5，硬上限 `awaken_percent_cap`（默认 0.95）。

**实现**：
- 入口：`LivingAttackEvent` -> `CombatAbilityHandler.onLivingAttack()`
- 通过门禁后计算闪避率 `(AGILITY_BASE + AGILITY_PER_MILESTONE × (count - countAtUnlock)) / 100`，`player.getRandom().nextFloat()` 判定
- 命中闪避则 `event.setCanceled(true)` **在伤害进入减伤/护甲计算前整体取消**，并生成 20 枚 `WITCH` 粒子反馈
- 觉醒：`(value/100) × AWAKEN_MULTIPLIER`，硬钳制 ≤ `awaken_percent_cap`（默认 0.95），防止完全无敌

配置：`agility_base`(10) / `agility_per_milestone`(7) / `awaken_multiplier`(1.5) / `awaken_percent_cap`(0.95)

### 大地之力 `digging_power`

**效果**：挖掘速度 ×1.3 -> ×1.75，觉醒后约 ×2.625，且无视水中/空中挖掘惩罚。

**实现**：
- 入口：`PlayerEvent.BreakSpeed` -> `ExplorationAbilityHandler.onBreakSpeed()`
- `event.setNewSpeed(originalSpeed × multiplier)`，纯事件层实现，无 Mixin，兼容性最好
- 觉醒：反向补偿原版 `getDestroySpeed` 的挖掘惩罚 -- 眼在水中且无水下速掘附魔时 `/5`、未着地时 `/5`，觉醒时各 `×5` 补回，叠加 `×1.5` 倍率（飞行/游泳也无惩罚）

配置：`digging_power_base`(1.3) / `digging_power_per_milestone`(0.05) / `awaken_multiplier`(1.5)

## 里程碑 2 · 初尝败绩

### 虚空踏步 `void_step`

**效果**：空中可再次跳跃（二段跳），清空摔落距离。觉醒后获得「御风」：疾跑时二段跳朝视角方向水平冲刺，松开疾跑为纯垂直跳。

**实现**（客户端预测 + 服务端权威，两端共用 `VoidStepMovement` 施力公式）：
1. **客户端**（`JumpInputHandler`，钩子 `MovementInputUpdateEvent`，与原版跳跃同 tick 生效）：边沿检测 `input.jumping`（按一下跳一次，松开再按再触发）；本地维护 `clientJumpsUsed`（空中仅允许 1 次，落地清零）；条件满足时调 `VoidStepMovement.applyJump(player, power, dash)` 做即时预测（`dash = 觉醒 && 疾跑`，觉醒疾跑时附加御风冲刺），发送 `DoubleJumpPacket`
2. **服务端**（`DoubleJumpHandler.handleDoubleJump(player)`，网络包处理）：重新校验门禁（不骑乘/不在水中/不在飞行；**刻意不校验 onGround**——客户端已在 !onGround 时才发包，服务端再校会因网络延迟误杀）；`AIR_JUMPED` Set 记录本空中周期已跳（落地清零由 `PlayerTickDispatcher` 分发的 `DoubleJumpHandler.onTick` 检测 onGround 完成），每周期仅允许 1 次；**v1.3.1**：鞘翅滑翔 / 攀爬不触发二段跳（客户端与服务端条件对称）；调 `VoidStepMovement.applyJump(player, power, false)`（**只设 Y，不施加御风冲刺**，对齐云朵瓶：水平冲刺由客户端预测，位置客户端权威，避免两端 sprint 状态不同步导致水平跳变）
3. 跳跃力：`0.42 × 方块 JumpFactor + 跳跃提升加成`，整体 × `VOID_STEP_POWER`（默认 1.2）；Y **直接覆盖**（对齐原版 `jumpFromGround`，无 max 弹跳感）；`fallDistance = 0`；**成功不发包**（信任客户端预测，两端 Y 同公式无顿挫），拒绝时才发 `ClientboundSetEntityMotionPacket` 拉回防独飞
4. **`VoidStepMovement`**：两端共用 `calculateJumpPower` / `applyJump(power, dash)`；`dash=true` 时朝 `YRot` 施加 `AWAKEN_VOID_STEP_DASH` 水平冲刺。**v1.3.0 动量物理**：二段跳保留当前水平速度（`motion.x/z` 不变），跑得快自然跳得远；御风冲刺冲量随当前移速加成（`dashAmount × 当前移速 / 基础移速`），跑得快冲得远--与加速（`swift`）属性联动
5. 生命周期：登出 / 死亡重生（Clone）/ 落地清理 `AIR_JUMPED`；客户端在死亡重生/换维度（玩家引用变化）时重置 `clientJumpsUsed` / `wasJumpDown`，防旧玩家状态残留
- 觉醒「御风」：`dash = 觉醒 && isSprinting()`，疾跑时二段跳朝视角方向水平冲刺（`AWAKEN_VOID_STEP_DASH` 默认 0.6，随移速加成），松开疾跑纯垂直跳

配置：`void_step_power`(1.2) / `awaken_void_step_dash`(0.6)

### 受击坚韧 `resilience`

**效果**：每次受击叠 1 层，每层减伤 5%，5 秒未受击清零。上限 5/8/12 层（里程碑 8/9/10），觉醒 +6 层（最高 18 层 = 90% 减伤）。

**实现**：
- 入口：`LivingHurtEvent` @**LOW** -> `PlayerStateHandler.onLivingHurt()`--低优先级保证拿到其他减伤都算完后的最终伤害
- 先按当前层数减伤 `event.setAmount(amount × (1 - stacks × 0.05))`，再叠层（不超过 `ResilienceAbility.value(count, awakened)` 上限）、刷新 `lastHurtTime`
- 层数与时间戳存 Capability（NBT 键 `resilienceStacks` / `lastHurtTime`），跨重生持久
- 过期清零：`PlayerTickHandler.onTick` 检查 `当前 - lastHurtTime ≥ RESILIENCE_RESET_TICKS`(100)

配置：`resilience_stacks_8`(5) / `resilience_stacks_9`(8) / `resilience_stacks_10`(12) / `resilience_damage_reduction_per_stack`(0.05) / `resilience_reset_ticks`(100) / `awaken_resilience_bonus_stacks`(6)

### 净魂 `purified_soul`

**效果**：免疫所有负面药水效果（根本不会被施加，无图标闪烁）。觉醒后周围 16 格敌对生物持续获得虚弱 II。

**实现**（Mixin 源头拦截 + tick 兜底双轨）：
- **Mixin 层**（`PurifiedSoulMixin`，priority=2000）：注入 `LivingEntity.canBeAffected()`（SRG `m_7301_`）@HEAD，效果类别为 `HARMFUL` 且玩家启用净魂时 `cir.setReturnValue(false)`--原版施加逻辑在入口就被判"免疫"，**效果从未被添加过**。门禁与其他能力 Mixin 统一：`ProgressCache` 按 tick 缓存 progress 引用 + `isAdventurer() || isFullyUnlocked()` 身份检查 + `isAbilityEnabled`
- 为什么不用 `MobEffectEvent.Applicable`：该事件在 Forge 1.20.1 不可取消，调 `setCanceled()` 会抛 `UnsupportedOperationException`
- **tick 兜底**：`PlayerStateHandler.onTick` 每 tick 扫一遍 `getActiveEffects()`，收集后统一移除漏进来的 HARMFUL 效果（先收集再 remove 防 ConcurrentModificationException；覆盖 NBT 直接注入、药水云等 Mixin 拦不到的路径）。**v1.3.8**：移除改走 `removeHarmfulBypassEvents`——`removeEffectNoUpdate` 直删效果表 + 反射 `onEffectRemoved`（SRG `m_7285_`），绕过可被取消的 `MobEffectEvent.Remove` 事件（整合包模组取消事件时 `removeEffect` 静默失败；且 `MobEffectEvent.Expired` 被取消的效果会以 0 时长永久残留、客户端 0:00 去不掉）；副作用（属性修饰符清除/客户端移除包/成就触发器）与原版完全一致，详见版本演进摘要 v1.3.8
- 觉醒虚弱光环：每 `awaken_purified_soul_aura_interval`（40）tick 对半径 `awaken_purified_soul_radius`（16）内的 `Monster` 施加 `awaken_purified_soul_weakness_amplifier`（默认 1=虚弱II）级虚弱，持续 `awaken_purified_soul_weakness_duration`（默认 100 tick）；刷新余量 = min(时长的 60%, 施加间隔)，配置短时长也不断档。施加错峰 `(gameTime + playerId) % interval` 分散服务器压力，重施条件为 amplifier 或时长不足（不每次覆盖）

配置：`awaken_purified_soul_radius`(16) / `awaken_purified_soul_aura_interval`(40) / `awaken_purified_soul_weakness_amplifier`(1) / `awaken_purified_soul_weakness_duration`(100)

### 满载而归 `loot_all`

**效果**：击杀生物后，在原版掉落基础上额外按掉落表"每样一份"追加掉落，无视 entry/pool/function 三级 LootItemCondition（特定方法杀 Boss、火杀熟肉等条件性掉落不用满足也掉）。觉醒后每样取掉落表最大数量。

**实现**（LivingDropsEvent + 4 Mixin + 双 ThreadLocal 标志位）：
- 入口：`LootAllHandler.onLivingDrops()` @FORGE -> 攻击者追溯用 `PiercingGazeUtil.resolveAttacker`（**v1.3.3**：弹射物击杀（弓/弩/三叉戟）的 `getEntity()` 是弹射物本身，原实现只认近战击杀；与 `MilestoneTriggerManager.onPlayerFirstKill` 的追溯逻辑一致）+ `isAbilityEnabled("loot_all")` 门禁 + **友伤保护**（`FriendlyFireProtection.isOwnerTarget`，杀自家驯服生物不掉额外掉落），**不清空原版 drops**，额外调 `LootTable.getRandomItems(params)` 追加 `ItemEntity`，`max_items` 上限防极端配置卡服。构造 params 时显式传入 `THIS_ENTITY`/`ORIGIN`/`DAMAGE_SOURCE`/`KILLER_ENTITY`/`DIRECT_KILLER_ENTITY`/`LAST_DAMAGE_PLAYER` 六参数（`LAST_DAMAGE_PLAYER` 影响 `killed_by_player` 类条件的判定）
- **Mixin 1**（`LootPoolEntryContainerMixin`）：`@Inject` `canRun`（SRG `m_79639_`）@HEAD，BYPASS=true 时返回 true -> 无视 **entry 级**条件
- **Mixin 2**（`LootPoolMixin`）：`@Inject` `addRandomItems`（SRG `m_79053_`）@HEAD cancellable，BYPASS=true 时遍历 `entries` 各调 `expand` -> `createItemStack`（打破 weight 单选，每样一份）+ cancel 原 rolls 逻辑 -> 无视 **pool 级**条件
- **Mixin 3**（`LootContextBuilderMixin`）：`@ModifyArg` `LootContext.Builder.create`（SRG `m_287259_`）拦截 `new LootContext` 构造的 random 参数（index=1），BYPASS 与 AWAKEN **同时为 true** 时注入 `ConstantMaxRandomSource` -> `SetItemCount` 取最大数量
- **Mixin 4**（`LootItemConditionalFunctionMixin`）：`@Redirect` `apply` 内 `compositePredicates.test`，BYPASS=true 时返回 true -> 无视 **function 级**条件（如 `SmeltItemFunction` 的 `on_fire`，非火杀也熔炼成熟肉）。**`require = 0, remap = false`（v1.4.0 补 `expect = 1`）**：MC 版本升级后若 `apply()` 内联该调用，注入点缺失会在日志输出 WARN（不再纯静默，见 v1.4.0 条目）——满载归还唯一可能退化的层
- 标志位 save-restore：`BYPASS`/`AWAKEN` 用 `ThreadLocal`，`finally` 恢复前值（防嵌套 LivingDropsEvent 重入破坏外层标志位）
- `entries` 字段经 `LootPoolAccessor` `@Accessor` 暴露（refmap `f_79023_`）；抢夺通过 `KILLER_ENTITY` 自动随玩家（1.20.1 `getLootingModifier` -> `ForgeHooks.getLootingLevel`）
- **额外掉落过滤（v1.3.7，`LootAllHandler.isFiltered`）**：黑名单 / 唱片 / 头颅三项独立配置，**仅过滤额外掉落，原版掉落不受影响**；默认均不过滤（`loot_all_blacklist` 默认空列表；`loot_all_drop_music_discs`/`loot_all_drop_skulls` 默认 **true** = 允许掉落，设为 false 才启用过滤），保持与旧版本完全一致的行为。背景：其他模组往掉落表塞头颅/唱片时，"每样一份"会把它们全部爆出——不是满载本身的 bug（我们只拿表 + Mixin 注入），加过滤让玩家自选。黑名单按物品注册 ID（`loot_all_blacklist`，如 `"minecraft:player_head"`）；唱片按类判断（1.20.1 为 `RecordItem`，原版+模组唱片统一拦截，不依赖注册名）；头颅按 `minecraft:skulls` 物品 tag（**1.20.1 原版无此 tag，作数据包扩展点**，`TagKey.create` 直接引用）+ 注册名 `*_skull`/`*_head` 后缀兜底（覆盖原版 6 种头与大部分模组头）

**边界**（非 loot table 掉落无法覆盖）：
- Forge GlobalLootModifier (GLM) 类掉落（如星月纯净之星）- 独立于 loot table，拿不到
- `dropCustomDeathLoot` 代码 spawn（如诡厄巫法隐匿蓝图）- 不走 loot table，拿不到
- `AlternativesEntry`（or）只给首个 alternative - 符合"任选一"语义，非 bug

配置：`loot_all_copies`(1) / `loot_all_max_items`(100) / `loot_all_blacklist`([]) / `loot_all_drop_music_discs`(true) / `loot_all_drop_skulls`(true) / `loot_all_awakened_max_count`(true) / `loot_all_awakened_copies`(2)

## 里程碑 9 · 终末之翼

### 翱翔 `soar`

**效果**：获得创造模式飞行。觉醒飞行速度 ×1.5。

**实现**（核心难点：与其他模组的飞行来源共存）：
- 入口：`PlayerStateHandler.onTick()`(END，由 `PlayerTickDispatcher.onPlayerTick` 分发) 每 tick 对账
- 授予：`abilities.mayfly = true` + `onUpdateAbilities()`，同时在 Capability 记 **`soarGrantedFlight = true`**--"这个 mayfly 是翱翔给的"。注意 `grantMilestone()` 解锁即时授予与开局安全网两条路径**不置** `soarGrantedFlight`（依赖下一 tick onTick 补标记）
- **精准回收**（v1.1.6 修复）：tick 对账路径关闭能力时必须同时满足 ①当前 mayfly=true ②`soarGrantedFlight == true` ③非创造非旁观，才回收。**装备鞘翅环、其他模组给的飞行不会被误没收**。能力面板（`AbilityTogglePacket`）手动关闭走 `applySoarState(false)`，回收条件与 tick 对账一致——两条关闭路径行为统一；回收时同时 `flying = false` + `flyingSpeed` 重置 0.05
- **无条件清标记**：两条关闭路径在回收分支之外**无条件置 `soarGrantedFlight = false`**（不依赖 mayfly 条件）——关闭时若没在飞（回收分支条件不满足）也不残留标记，否则之后其他来源（套装等）授予的 mayfly 会被回收分支误判为翱翔给的而没收（v1.3.1 实测排查修复）
- 飞行速度写 `flyingSpeed` 字段，只在与目标值偏差 > 0.0001 时写入--防止每 tick 重复乘法导致速度指数爆炸；**v1.3.3**：仅觉醒时覆盖（觉醒倍率写入后补 `onUpdateAbilities()` 同步客户端——`setFlyingSpeed` 不会自动发包，客户端 LocalPlayer 保持旧速度直到下次 abilities 同步）；非觉醒保持原版 0.05，不覆盖其他模组对 flyingSpeed 的设定
- 时序处理：`Clone` 跨维度保留飞行中状态；`PlayerChangeGameModeEvent` 立即重新授予（**v1.2.8：玩家在空中时自动设 `flying=true` 防坠落**，地面保留双击空格触发）；`grantMilestone()` 解锁时立即同步（不等下一 tick，消除竞态）

配置：`awaken_soar_speed`(1.5)

### 淬魂之力 `soul_quench`

**效果**：攻击附加真实伤害：`固定值 + 目标最大生命% + 当前生命%`（9/10 里程碑两档：2+1%+1% / 4+2%+2%）。对禁疗标记中的目标 ×1.5。觉醒后目标血量 ≤`awaken_soul_quench_execute_threshold`（默认 20%）时伤害 ×`awaken_soul_quench_execute_multiplier`（默认 2.0，斩杀线）。**命中反馈（v1.3.7）**：结算完成后目标处播放灵魂蓝火粒子（`soul_quench_particle_count`，0 = 关闭）。

**实现**：
- 入口：`LivingHurtEvent` -> `CombatAbilityHandler.handleSoulQuench()`
- 追加伤害用**自定义伤害类型 `adventure_power:soul_strike`**（`data/adventure_power/damage_type/soul_strike.json`，datapack 标签配置为绕过护甲/无敌/附魔/攻击冷却）走一次独立 `target.hurt()`
- 防递归：`isInternalSource()` 检查伤害源 msgId 是 `soul_strike`/`judgment`/`shadow_kill`（v1.3.1 起含影杀）则跳过（否则自己的追加伤害会再触发自己）
- 伤害后立即 `invulnerableTime = 0` + 反射清 `hurtTime`（部分 Boss 拿 `hurtTime>0` 当额外无敌判据）
- **直写补刀**：比较 `实际造成 < 期望 - ε`，说明 hurt 被外部拦截 -> 直写修正后血量（**v1.3.5 起分级直写**：通用 setter 扫描 → 对象图插针 → DataItem 按值匹配三级链——真血在普通字段的 Boss（亚波伦 `FloatWrapped`、灵梦 `CombatProgress`）不再打空；v1.3.5 前为 `setAllHealthLikeRaw` 单级；**v1.4.2 起由 `BloodWriteEngine.execute` 接管**——五层引擎磨血语义，见 v1.4.2 条目；**v1.4.3 入口清盾前置**——`MultiStoreWriter.clearShieldComponents` 清护盾类次分量、目标值以清盾后读数为基，见 v1.4.3 条目）；归零则 `setLastHurtByMob/Player(attacker)`（击杀归属）——**v1.4.3 起不再主动 `die()`**（磨血能力语义是"伤害"非"处决"，主动 die 制造半开门状态[die 事件已发、死亡流程未走完]被遭遇/复活系统当"战斗中断"恢复；写 0 后对面自然死接管，处决由影杀兜底；`setDeathScoreNegativeOne` 随之删除，见 v1.4.3 条目十七/十九轮）。历史：v1.3.5 前归零强制 `target.die(source)` + 置 `deathScore = -1`，v1.3.5 计分移到 `die()` 之后 + `isAlive` 确认（死亡被死亡抗拒等救回时不再发放击杀分）
- **PVP 禁用（v1.3.6）**：入口 `target instanceof Player` 直接返回——淬魂按真实血量（`getEffectiveHealth`）计算百分比伤害，对玩家目标会扫到冒险者自身的真实血条备份（true_health 通道），且兜底直写含对象图插针，与玩家侧防御体系冲突（与禁疗/破敌 PVP 禁用对称）
- **命中反馈（v1.3.7）**：结算完成后 `serverLevel.sendParticles(SOUL_FIRE_FLAME)` 广播（目标躯干中心，0.3 扩散，`soul_quench_particle_count` 默认 6）——PVP 禁用路径直接 return 天然不触发；纯服务端广播，不依赖客户端

配置：`soul_quench_flat_damage_9/10`(2/4) / `soul_quench_hp_ratio_9/10`(0.01/0.02) / `soul_quench_healing_block_multiplier`(1.5) / `soul_quench_particle_count`(6) / `awaken_soul_quench_execute_threshold`(0.2) / `awaken_soul_quench_execute_multiplier`(2.0)

### 破敌之眼 `piercing_gaze`

**效果**：攻击无视一切无敌--原版无敌帧、模组 Boss 的自定义无敌、限伤、"必须先破条件才能打"的机制统统穿透。觉醒后破无敌一击，目标 3 秒内无法获得无敌帧。**穿透反馈（v1.3.7）**：穿透成功时目标处播放屏障破碎音效 + 玻璃碎片粒子（`piercing_gaze_feedback_enabled`，同目标同 tick 只反馈一次，穿透三连不刷屏）。

### 恩赐永驻 `perpetual_blessing`

**效果**：正面药水效果持续时间低于保底阈值时自动续期，Buff 永不自然耗尽。玩家可在统一面板（P 键 -> Buff永驻标签）把不想续的效果加入黑名单。

**实现**：
- 入口：`PlayerTickDispatcher` 分发的 `PlayerTickHandler.onTick()`，用 `lastBuffCheck` Map 节流为每 60 tick 检查一次（**限频基准用服务器全局 tick**（v1.3.5）：`lastBuffCheck` 静态 Map 不随 `shiftTimers` 平移，用维度 gameTime 在进入时间轴更小的维度时会冻结；Capability 时间戳字段仍用 gameTime 由 `shiftTimers` 平移）
- `extendBeneficialEffects()`：遍历 `player.getActiveEffects()`，只处理 `MobEffectCategory.BENEFICIAL`；效果剩余时间 < `阈值 = BUFF_MIN_DURATION + BUFF_EXTEND_AMOUNT` 时用新 `MobEffectInstance` 覆盖（保留 amplifier/ambient/visible 参数；**v1.3.1 起同时保留 factorData**——潮涌能量等环境效果数据不再因续期丢失）；**v1.3.3**：先跳过 `duration < 0` 的无限时长效果（`MobEffectInstance.INFINITE_DURATION`，潮涌能量/部分模组永久 buff）——否则 `-1 < 阈值` 恒真，无限效果被降级为有限时长并每 60 tick 反复重建 + GLOW 粒子刷屏；有续期发生时向附近广播 15 枚 GLOW 粒子反馈
- 黑名单存在 `player.getPersistentData()` 的 `MME_BuffBlacklist` 键下，跨死亡持久；运行时按 UUID 缓存黑名单（每 60 tick 免 NBT 解析），toggle 时失效、登出清理；`onPlayerClone` 手动转移该 key（Forge Clone 不复制根级自定义 key）
- 觉醒：正面效果无法被驱散 -- 监听 `MobEffectEvent.Remove`（实现位于 `AdventureProgressCapability.onBeneficialEffectRemove`，capability 包而非 handler 包），觉醒+恩赐永驻开启时对 `BENEFICIAL` 效果取消移除。覆盖 `removeEffect` / `removeAllEffects` / `cureEffects`(牛奶桶) 三条主动移除路径；自然过期走独立的 `MobEffectEvent.Expired` 不受影响。负面/中性照常可清

**配置**：`buff_min_duration`(400，保底阈值) / `buff_extend_amount`(0，额外延长量；为 0 时阈值即保底值 400 tick)。该能力无成长，解锁即完整。觉醒「无法驱散」无配置项，固定生效。

### 影杀 `shadow_kill`

**效果**：为攻击目标投影一条"影子血量"（紫色 Boss 栏显示，多人各自独立）。每次攻击削减 `4 + 目标总血量 4%`，与目标真实血量无关--**无论 Boss 怎么回血、锁血、免疫，影子血量只减不增，归零即斩杀**。觉醒后斩杀触发 8 格 AOE，削减周围怪物 15% 影子血量并可连锁斩杀。PVP 无效。

### 真实血量 `true_health`

### 拒绝篡改 `reject_manip`

**效果**：拦截外部模组对玩家血量的非法直接修改（不经过伤害流程的 `setHealth` 降血 / `SynchedEntityData.set` 直写，后者为 v1.3.8 数据同步层）和 maxHealth 恶意压低。觉醒后把被拦截的降血量按 30% 反弹给最后攻击者。

**实现**（与真实血量分工：本能力拦"写入"，真实血量修"已写入"）：
- **HURT_DEPTH 标记**（`RejectHealthManipMixin`）：`hurt()`（`m_6469_`）@HEAD 时 ThreadLocal 计数 +1，@RETURN 时 -1。由此区分"hurt 内部的合法 setHealth"与"外部直调 setHealth"。服务端主线程单线程，ThreadLocal 天然隔离调用链，无锁无查表。**v1.3.1**：外部模组以低优先级 Mixin cancel `hurt()` 时 RETURN 不执行、深度残留 +1——`HealthUtil.resetHurtDepthPerTick()` 在 ServerTickEnd 无条件归零（hurt 不跨 tick，tick 末深度必为 0 是不变量），泄漏窗口仅为 cancel 发生的同 tick 内
- **setHealth 拦截**（`m_21153_` @HEAD）：NaN/Infinity 直接 cancel；回血放行；`HURT_DEPTH > 0` 放行；其余（外部直调降血）-> `ci.cancel()`
- **maxHealth 底线**（`RejectHealthManipAttributeMixin`，`AttributeInstance.setBaseValue()`（`m_22100_`）@HEAD）：新值 < 6.0（3 颗心）时先 O(1) 查 `ATTR_OWNER` 映射找所有者，未命中（getAttribute 未被调用的早期路径）再 fallback 遍历在线玩家并补登记。是受保护玩家则 cancel
- 共享的 `ATTR_OWNER` Map 放在 `RejectHealthManipUtil` 工具类（Mixin 类禁止非 private static 成员）；登记注入点：`getAttribute`（`m_21051_`）@RETURN 时对冒险者/觉醒玩家登记"AttributeInstance -> 所有者"；`remove()`（`m_142687_`）@HEAD 注入 `cleanupOnRemoval`，实体卸载时从 `ATTR_OWNER` 移除其映射，防内存泄漏
- 觉醒反弹：`(当前血量 - 目标写入值) × 30%` 以魔法伤害反弹给 `getLastHurtByMob()`

配置：`awaken_reject_manip_reflect_ratio`(0.30)

### 旅者之力 `active_skill`

**效果**：解锁两个主动技能（Y 切换 / G 释放，共享 0.5 秒 GCD）：
- **旅者审判**（30 秒 CD）：对周围 6 格敌对生物造成 `10 + (最大生命 + 当前生命) × 3% × 里程碑数` 的范围伤害。觉醒范围 ×1.5（9 格）
- **旅者庇护**（90 秒 CD）：5 秒无敌 + 清负面 + 灭火。觉醒后庇护期间可以 30% 速度移动

**实现**：
- 链路：客户端 `InputHandler`（Y 键切换 / G 键释放，本地预检 GCD/CD 减少无效包）-> **v1.3.1 新增 `SkillSwitchPacket`**（Y 键切换改由服务端持久化并回同步，切换状态不再被任意 sync 覆盖重置；服务端拒绝时也回发同步让客户端乐观更新回滚）-> `ActiveSkillPacket` -> 服务端 `ActiveSkillHandler.handleSkillRelease()` **重新完整校验**（skillIndex 范围、`isFullyUnlocked`、能力启用、GCD、各技能 CD--v1.1.8 加固的防御性自门禁）
- **审判**（`executeJudgment`）：自定义伤害类型 `adventure_power:judgment`；**v1.2.8 改为排除玩家/驯服生物，其余都打**（不再限定 Monster，覆盖史莱姆/幻翼等）；血量判断改用 `getEffectiveHealth`（v1.3.4 架空参照统一：防 ASM 篡改读数 + 自定义血条 Boss 正确读血；v1.2.8 原为 `getHealthDirect`）；带与淬魂相同的**直写补刀**（实际伤害不足 -> 直写修正：**v1.4.2 起由 `BloodWriteEngine.execute` 接管**[磨血语义，v1.4.2 前为 `setAllHealthLikeRaw`，见 v1.4.2 条目]；**v1.4.3 补清盾前置**——目标值以清盾后读数为基；**v1.4.3 起归零不再主动 `die()`**——与淬魂同款十七轮定调[磨血不制造半开门]，写 0 后对面自然死接管，处决由影杀兜底）；补刀时同时重置 `invulnerableTime = 0`、`setLastHurtByMob/Player`（击杀归属；`deathScore = -1` 置位随 v1.4.3 die 移除一并删除，见 v1.4.3 条目十七/十九轮）
- **庇护**（v1.2.1 补全无敌与移动锁）：
  - 写 Capability 的 `sanctuaryInvulEnd`，过期由 `PlayerTickHandler.onTick` 清零并同步
  - `PlayerStateHandler.onSanctuaryDamage`（`LivingAttackEvent` @HIGHEST）在无敌期内 `event.setCanceled(true)`，但 `DamageTypeTags.BYPASSES_INVULNERABILITY`（`/kill`、虚空等）**照常放行**，防止玩家用庇护规避管理员指令或掉出世界
  - **非觉醒**期间移动速度锁 0（完全定住不能走），**觉醒**才允许 `AWAKEN_SANCTUARY_SPEED`（默认 0.3）倍减速移动；**v1.2.8：庇护结束时恢复原始移动速度**（记录 `ORIGINAL_MOVE_SPEED`，不硬编码 0.1，不覆盖其他模组修改）；**v1.3.3**：else 分支加残留判定——无记录时（服务端重启后 Map 清空、player.dat 已落盘庇护目标值 0/0.03）若当前 baseValue ≈ 模组庇护目标值则回归原版 0.1，否则视为其他模组修改不覆盖（与 maxHealth/reach 残留判定同模式，修复重启后玩家永久无法移动）。**v1.4.3-fix**：改挂固定 UUID 的 ADDITION modifier——非觉醒挂哨兵负值（-5.0，MOVEMENT_SPEED clamp 下限 0，外部 base 修改/正加成均不可抵消，绝对定身语义保持）、觉醒挂精确负值压到目标速度（语义为"慢速移动"非绝对锁死）；`ORIGINAL_MOVE_SPEED` 与残留判定全删（庇护结束移除 modifier 即恢复，不触碰 base）；旧版写 base 的庇护残留（0 或 0.1×配置）仍保留同款判定还原 0.1，防移动永久锁死。详见版本演进摘要 v1.4.3-fix
  - `event.isCanceled()` 前置检查，避免重复拦截其他能力已取消的事件
- 冷却全部存 Capability（NBT 持久化，重登不重置），释放后 `syncToClient` 驱动 HUD（`ActiveSkillHudOverlay`）显示冷却环
- 觉醒联动：死亡抗拒触发时直调 `executeJudgment()`，绕过 CD 和 GCD（免费审判）

配置：`active_skill_judgment_base_damage`(10.0) / `active_skill_judgment_hp_ratio`(0.03) / `active_skill_judgment_radius`(6.0) / `active_skill_judgment_cooldown`(600) / `active_skill_sanctuary_duration`(100) / `active_skill_sanctuary_cooldown`(1800) / `active_skill_gcd`(10) / `awaken_judgment_range_mult`(1.5) / `awaken_sanctuary_speed`(0.3)

## 附录：能力联动关系

- **虚空踏步 × 加速**：御风冲刺冲量随当前移速加成（`dashAmount × 移速/基础移速`），跑得快冲得远
- **淬魂之力 × 禁疗之触**：对禁疗标记中目标伤害 ×`soul_quench_healing_block_multiplier`(1.5)
- **死亡抗拒 × 旅者之力**：觉醒触发时免费释放一次审判（不消耗 CD、不占 GCD）
- **真实血量 × 拒绝篡改**：分工明确——拒绝篡改拦「写入」（`setHealth` 拦截），真实血量修「已写入」（getHealth 时检测修复）；两者共享 `HURT_DEPTH` 标记判定合法伤害
- **破敌之眼 × 影杀/嗜血等监听器**：Layer 0 放行时手动 post `LivingHurtEvent`，保证被 ASM 改 hurt 的模组跳过原版事件时，影杀/嗜血等事件监听器仍能触发
- **嗜血 × 伤害抗性**：嗜血改 @LOW 基于减伤后最终金额吸血，消除与伤害抗性的顺序不确定性
- **影杀/淬魂/审判 × 嗜血**：内部伤害源（`soul_strike`/`judgment`/`shadow_kill`）不触发二次吸血（`isInternalSource`）
- **磁吸 × 经验加成**：磁吸觉醒吸取的经验球同样走原版拾取流程，经验加成补差额照常生效
