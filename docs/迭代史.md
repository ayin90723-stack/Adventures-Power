  - **禁疗双源改造**：启示录亚波伦（RevelationFix 版 `Apostle`）重写 `getPersistentData()` 每次返回全新空 tag——禁疗 NBT 标记 `MME_UndyingSlashEndTime` 写入即丢、`isActive()` 永远 false，`LivingHealEvent` cancel / Mixin tick TAIL / `ServerTickEnd` 三层钳制全部失效（亚波伦正常回血）。修复：`HealingBlockEffect.TRACKED_HEALTH` 升级为 `TrackedEntry`（血量低点 + 到期时间）内存/NBT 双源，`isActive()` NBT 优先、内存表回退（钳制链不因 NBT 失效，代价：此类实体重启后标记丢失）；觉醒易伤 `VULN_END` 同步双源化（`applyVuln`/`getVulnEnd`/`removeVuln`），清理路径（tick 过期/死亡/二阶段豁免/2 tick 宽限）四处统一。
  - **架空参照读数统一**：敌方目标侧的血量基准/扣血检测（禁疗钳制 4 处、淬魂 hpRatio 基准/斩杀线/补刀检测、破敌之眼 Layer 0 扣血比对/Layer 2 healthBefore/afterPierceFallback、审判 hpRatio 基准/补刀检测）从 `getHealthDirect`（原版 DataItem）统一改为新增的 `HealthUtil.getEffectiveHealth()`（架空参照：`|getHealth() - getHealthDirect()| > 1.0` 判定原版血条被架空时取 `getHealth()` 真实血量，否则回落 DataItem 防 ASM）——修复自定义血条 Boss（亚波伦）原版槽架空导致的"回血钳制检测不到/百分比伤害失真/直写兜底恒触发数值错位"；玩家侧防御（TrueHealth/死亡抗拒/拒绝篡改/休养生息）保持 `getHealthDirect` 防 ASM 篡改不变。
  - **破敌之眼**：① **Layer 2.5 `@Redirect` 移除**——Forge 1.20.1 的 `ForgeHooks.onLivingHurt` 调用点位于 `actuallyHurt`（`m_6475_`）而非 `hurt`（`m_6469_`），旧 redirect 是死靶且 `require=0` 静默失效，posted 判定恒 false，对"调 super 扣血但 return false"的 Boss 恒走补 post + 二次 actuallyHurt（双重扣血）② **事件已发标记布尔 → 单调递增计数**（`VANILLA_HURT_EVENT_POST_COUNT` + Layer 0 `beginVanillaHurtScope` 作用域基线 / Layer 2 栈帧 `postedBase`）——布尔 clear 在嵌套 hurt（Boss 管线内递归 AoE、风暴守卫跳过的递归）时清掉外层标记，外层误判"未 post"补发 + 再次 actuallyHurt 双倍结算；计数按基线比较增量天然栈式隔离，无需压栈恢复 ③ **`shouldPierce()` 门禁统一**：攻击者持能力 + 非友伤 + 非玩家目标（PVP 禁用）从三处注入点收敛到 `PiercingGazeUtil` 单一入口（新增排除条件只改一处）④ **PVP 禁用**（用户决策）：破敌之眼（穿透三连绕过 PVP 保护类模组的伤害取消；觉醒禁无敌帧同步排除玩家）与**禁疗之触**（禁疗标记含 FORCE_KILL 强制击杀链，击穿玩家自身死亡抗拒/真实血量防御属行为自冲突）对玩家目标一律不生效 ⑤ **攻击方能力恢复 `event.isCanceled()` 检查**（v1.2.5 曾取消该检查以"被取消仍结算"，职责改由破敌之眼穿透覆盖——手动 post 的事件本身未取消；`receiveCanceled = true` 保留，作用变为保证事件已发计数 mark 不因取消丢失）。
  - **网络加固**：`BuffBlacklistSyncPacket` decode 长度限制（C2S 请求 128 / S2C 广播 2048，防恶意 OOM）、`AdventureSyncRequestPacket` 全局 tick 节流（防刷包风暴）、`BuffTogglePacket` 恩赐永驻能力门禁 + effectId 注册验证。
  - **跨维度计时补充**：`PlayerChangedDimensionEvent` 在 `changeDimension` 与 `teleportTo` 双触发点均做时间基准偏移（1.20.1 维度切换不克隆玩家，`onPlayerClone` 路径覆盖不到；javap 字节码验证双 fire 点）。
  - **不动如山**：`LAST_WRITTEN` 保留检查 + 登出条件恢复（服务端重启后恢复不再覆盖其他模组对击退抗性 baseValue 的修改）。
  - **主动技能**：`collectJudgmentTargets` 抽取——审判空放（范围无目标）不消耗 CD。
  - **里程碑触发器**：5 个 handler 触发逻辑统一收敛 `triggerMilestones`（per-milestone 触发记录合并）；survive_night 排除固定时间维度（下界 fixed_time=18000 / 末地 6000，无昼夜）。
  - **UI**：里程碑行/悬停提示静态缓存 + refreshTick 改 gameTime 桶（降低渲染开销）。
  - **多代理终审**：4+3 轮全量审查（正确性/一致性/细节），修复 20+ 项（含 P2-1 自引入 bug——onHurtEnter 无条件 clear 破坏嵌套未发布伤害的外层标记、Monster import 包错误、误删 tick handler 恢复等），最终无 P0/P1/P2 遗留；删除与项目无关的 lcjar/（原版混淆类碎片）。
- **v1.3.5**：移除禁疗之触 **Boss 二阶段豁免**（`shouldAllowPhaseTwo` 方法 + `healing_block_allow_boss_phase_two` 配置项）——凋零/末影龙无"死亡→复活/进阶段"机制（启示录亚波伦的二阶段为血量触发、`die()` 仅防重入），豁免为无效分支；`onLivingDeathPreMark` 统一对全部被禁疗实体写 `FORCE_KILL` 标记，死亡锁定语义一致化（旧 TOML 中残留配置键被 Forge 忽略，不影响加载）。
- **v1.3.5 审查修复（并入）**：两轮多代理全面审查 + 终审（正确性/细节/一致性，30+ 修改点全部无 P0/P1）——
  - **破敌之眼**：① posted 判定升级 **per-entity**（`LAST_POSTED_PER_ENTITY` 弱引用表：实体 UUID → 最近 post 计数）——嵌套实体（Boss 在 hurt 管线内对另一实体 AOE）的事件增量不再污染本实体"已 post"判定，Layer 0 的 consume 与 Layer 2 的 posted 判定不再误判（淬魂等监听器不再丢失结算机会）② `IN_PIERCING` 风暴守卫迁入 `PiercingGazeUtil`（Layer 0/2 共用，@Mixin 类禁非 private static 方法 + Layer 0 需读写同一标记）③ Layer 0 穿透三连补风暴守卫（`set(true)/finally` 恢复旧值——嵌套在 Layer 2 情况 A 监听器链内时不清掉外层守卫）。
  - **攻击方能力同 tick 结算去重**：`COMBAT_TICK_DEDUP`（attacker:target，ServerTick END 清空，淬魂/影杀/禁疗/嗜血共享）——穿透三连双重 post（手动 `postHurtEvent` + `actuallyHurt` 内 `ForgeHooks.onLivingHurt` 二次 post）不再导致淬魂/嗜血同 tick 双结算（影杀原有 `SHADOW_KILL_TICKED` 双保险保留）。

    - **HealthUtil 五修**：① 装箱 Float 字段插针支持（getFloat/setFloat 对装箱字段抛异常，改走 get/set 装箱路径）② 插针路径含实体引用（如威胁表 Map<Player,Float>）时不缓存 WritePath——缓存会强引用实体防 GC，玩家实体泄漏修复 ③ 自定义血条槽缓存纳入级联失效（首扫结论依赖实例时点，扫描瞬间处于变形/护盾阶段会永久缓存空集）④ raw 值匹配容差按量纲派生（裸 0.01/1 在 ≥16M HP 处低于 float ulp 地板退化为等值匹配，违反量纲不变量⑦）⑤ 容器抹除补类内 Player guard（防御纵深与死亡收尾双工具对齐）
    - **处决善后"已移除早退"**（ExecutionFinalizer.finalizeKill）：killEntity 同栈自移除型目标（引擎某层写 0 命中时目标在自己的击杀链内完成移除，被 isRemoved 短路跳过善后段却仍会走到本方法）直接跳过——对已移除实体全段执行会在其自移除链已做过掉落/事件的前提下双掉落/双发 LivingDeathEvent；DeathFinalizer 同批补类内 Player guard（防御纵深对齐）
    - **InvulClearUtil 排除原版层**：字段清除跳过 Entity/LivingEntity 声明层（invulnerable/invulnerableTime）——被子串匹配误清后目标对全世界的伤害源（环境/其他攻击者）都不再无敌，能力效果外溢收束；破敌"本次攻击穿透"由 Layer 1 isInvulnerableTo 拦截实现不动原版字段，穿透功能不受影响
    - **mixin 配置双 priority 键语义澄清**：mixins.adventure_power.json 显式声明 `mixinPriority: 1000`——容器级 `priority`（-5000）是配置加载顺序、`mixinPriority` 才是注入点同调用点竞争优先级（v1.4.6 破敌 Layer 0 抢占事故的根源之一）；让位/抢占必须在 @Mixin 注解显式写 priority
  - **玩家体验修复**：
    - **冒险饰品死亡不掉落改暂存恢复**：1.20.1 死亡重生走 respawn(player, false)，restoreFrom(player, false) 在 keepInventory=false（原版默认）且非旁观者时**不复制物品栏**——原"移出掉落列表还回死亡玩家背包"的物品滞留在被丢弃的旧实体上凭空消失。修复：LivingDropsEvent 把饰品栈序列化暂存死亡玩家 persistentData 的 PlayerPersisted 子 tag（Forge Clone 自动复制），CapabilityLifecycleHandler.onPlayerClone 死亡 Clone 时写回新玩家背包（背包满掉重生点兜底）；掉落事件被取消（坟墓/墓碑类模组接管）时本处理器不干预
    - **真实血量/拒绝篡改：合法生命上限变化放行**：生命上限合法下移（诅咒装备/药水类机制改 maxHealth）触发的原版 clamp 归位此前被当非法降血拦截/修复——血量停在新上限之上直到下次受伤。修复：setHealth 拦截层对"写入值精确等于当前上限"放行（血 ≤ 上限时该值属升血方向已放行，能进到此分支的必然是高血归位）；真血读取层把 DataItem 读数精确等于当前上限的降值接受为合法归位并同步备份，不再修复拉锯
    - **死亡抗拒不白耗冷却**：同优先级其他模组监听器（复活类机制）先取消死亡时直接早退——玩家实际未被本能力救回，取消+回血+写冷却全属无效消耗
    - **翱翔关闭回收语义收紧**：`soarGrantedFlight` 标记只在**实际授予分支**置位——原实现每 tick 无条件置 true，mayfly 来自其他模组（一次性授予型飞行饰品等）时也被打上翱翔标记、关闭翱翔时被误没收；标记未置位时关闭翱翔不回收现飞
    - **灵魂绑定死亡快照防覆盖**：快照未消费（死亡被后序监听器救回、玩家存活且经验已清零）时跳过本次保存与清零——原实现用清零后的 0 现值覆盖旧快照、原经验永久丢失；旧快照留待下次真死恢复
    - **禁疗 FORCE_KILL 标记超窗清理**：内存表 Set → Map（值 = 打标时刻，主世界时钟统一基准），ServerTick END 超 100 tick 双清（NBT + 内存）——打标（HIGHEST）与消费（LOWEST）依赖同一次事件分发完整跑完，第三方处理器异常打断分发时条目永久残留，之后该目标与禁疗无关的复活会被误处决
    - **二段跳跨维度清理 + 网络限频补齐**：服务端 AIR_JUMPED/拒绝限频表在 PlayerChangedDimensionEvent 清理（1.20.1 传送门 changeDimension 不触发 Clone——空中跳后穿门标记带进新维度，落地前首跳被拒且不在地面时发拉回包产生一次可见顿挫）；DoubleJumpPacket/BuffTogglePacket 补 5 tick per-player 限频（恶意客户端刷空跳包每包付全价校验+粒子、Buff 切换包带 persistentData 写+回包放大，此前均无节流）+ 登出统一清理限频表
  - **数据/进度**：
    - **/reload 缩水窗口进度保留**：数据包删除里程碑或整体 enabled:false（注册表缩水）时，登录/死亡克隆的 NBT 装载此前按注册表 contains 过滤——被过滤的死 ID 从 Capability → persistentData → 物品 NBT 三层被逐层覆写丢失（obtain_item 类里程碑无法自愈）。修复：装载按原样保留死 ID（能力归属与计数隔离已由 rebuildAbilityCache 处理），饰品 NBT 回写对死 ID 同写照 true（新增 getUnlockedMilestoneIds 原始集），注册表恢复后进度原样回来
    - **/ap unlock ability 首次解锁清"手动关闭"标记**：首次指令解锁走不到 toggle 分支，disabledAbilities 残留导致命令报成功但能力实际仍关闭，且该能力已脱离里程碑归属、面板无 UI 入口无法自救——首次解锁同步 toggleAbility 清除
    - **里程碑 id 空白字符串拒绝加载**：空/空白 id 在 milestoneNbtKey 的 charAt(0) 抛 StringIndexOutOfBoundsException（服务端主线程 grant/sync 链崩服）——加载时跳过并 WARN
    - **禁用黑名单两处回退点保留**：数据包数组为空与 JSON 解析失败两处回退内置默认的路径此前未传黑名单——被禁能力在内置里程碑 abilities 中"复活"、/ap unlock ability 与觉醒门禁失效；loadBuiltinDefaults(Set) 重载并入外部黑名单
    - **空注册表恢复路径误激活修复 + 佩戴终点直接恢复**：空注册表（里程碑系统 enabled:false）时 count ≥ all.size()（0≥0 恒真）会把仅有指令解锁记录的玩家误激活 fullyUnlocked（不可逆，违背"永不回退"不变式）——空注册表跳过全解锁判定；佩戴「冒险的终点」本身即全解锁强证据，直接恢复 fullyUnlocked（数据包扩张 10→12 + capability 损毁叠加时数量判定会永远丢失觉醒状态）
    - **survive_night 标记消费前置**：注册表空检查提前 return 会短路标记消费——玩家熬过夜获得标记后 /reload 暂时移除 survive_night 里程碑，标记永不消费；里程碑重新加入后旧标记被直接解锁（跳过"度过一夜"达成条件）。消费移到注册表检查前
    - **饰品 tooltip 服务端守卫补 level==null**：原版 getTooltipLines 无玩家上下文时向 level 传 null，原守卫（level != null && !level.isClientSide()）对 null 不成立——专用服务器被第三方模组构建 tooltip 时走到客户端类抛 NoClassDefFoundError 崩服；改为 level == null || !level.isClientSide() 按服务端处理
