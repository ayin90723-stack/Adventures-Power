## 总体架构

### 三层实现模型

30 种能力按对抗强度分布在三个实现层，**优先使用高层，仅在高层无法覆盖时才下沉**：

| 层 | 手段 | 特点 | 典型能力 |
|----|------|------|----------|
| **事件层** | Forge 事件（`LivingHurtEvent`、`PlayerTickEvent` 等） | 兼容性最好，其他模组可感知 | 灵巧、大地之力、伤害抗性 |
| **Mixin 层** | 字节码注入原版方法（`hurt`、`setHealth`、`canBeAffected` 等） | 拦截事件系统覆盖不到的路径 | 净魂、不朽装备、死亡抗拒 |
| **反射直写层** | `HealthUtil` 直接读写 `SynchedEntityData` 内部字段、实体追踪结构 | 对抗其他模组的 Mixin/ASM 拦截，"最终手段" | 影杀、真实血量、破敌之眼兜底 |

### 生效门禁模型

每个能力的效果执行前统一走 `AbilityGate` 门禁链：

```
服务端检查（isClientSide 直接 return）
  -> AbilityGate.isAbilityActive(player, id)   // 冒险者/觉醒身份 + 能力开关（P 键面板）
  -> 觉醒分支（isFullyUnlocked()）               // 仅数值/机制强化层，不是准入门禁
```

- **里程碑制**：所属里程碑解锁后即可使用，不要求觉醒。
- 战斗监听器（`CombatAbilityHandler.onLivingHurt`）带 `receiveCanceled = true`——目的不是"取消后仍结算"，而是保证事件已发计数 `mark`（`PiercingGazeUtil.markVanillaHurtEventPosted`，破敌之眼 Layer 0 补发判定依赖）不因取消而丢失；**v1.3.4 起攻击方能力（淬魂/影杀/禁疗/破敌觉醒）与受伤方能力（伤害抗性）同样跳过已取消的事件**（攻击方分支显式 `event.isCanceled()` 检查）——被其他模组 cancel 的伤害（否定类机制）不再强行结算，攻击方伤害的生效保障由破敌之眼穿透（手动 post 的事件本身未取消）覆盖。
- 攻击者追溯：`source.getEntity()` 非 Player 时依次尝试 `getDirectEntity()`、投射物 owner，兼容拔刀剑/投射物 `causingEntity` 缺失的场景。
- 高频 Mixin 注入点（`getHealth`/`getAttribute`/`setHealth`）经 `ProgressCache` 按 tick 缓存 progress 引用，缓存的是引用而非门禁结果，能力开关/解锁/觉醒同 tick 即时生效。

### 数值成长公式

有成长的能力，数值随已解锁里程碑数（`count`）增长，`countAtUnlock` 为所属里程碑序号（`MilestoneRegistry` 动态填充）：

```
线性：value = BASE + PER × max(0, count - countAtUnlock)     // 灵巧、伤害抗性、加速等
步进：value = BASE + STEP × max(0, (count - countAtUnlock) / 2)  // 每 2 里程碑一档
固定：value = -1                                            // 解锁即完整
```

`max(0, ...)` 下限保护：允许任意顺序解锁，跳序解锁时差值不为负（否则会产生反向效果）。各能力成长类型一览：

| 成长类型 | 能力（countAtUnlock） |
|----------|----------------------|
| **线性**（`LinearGrowthAbility`） | 灵巧(1)、大地之力(1)、不动如山(3)、加速(3)、无形之手(4)、磁吸(4)、经验加成(5)、嗜血(6)、伤害抗性(6)、禁疗之触(7)、坚韧之躯(7) |
| **步进**（`StepGrowthAbility`，divisor=2） | 休养生息(2)、鸿运当头(5) |
| **无成长**（`AbstractAbility`，value 固定 -1） | 虚空踏步(2)、灵魂绑定(3)、全视之眼(4)、不朽装备(5)、环境免疫(6)、死亡抗拒(7)、净魂(8)、满载而归(8)、翱翔(9)、淬魂之力(9)、破敌之眼(9)、恩赐永驻(9)、影杀(10)、真实血量(10)、拒绝篡改(10)、旅者之力(10) |
| **特殊** | 受击坚韧(8)：三档 5/8/12 层（里程碑 8/9/10），觉醒 +6 层 |

> 注：死亡抗拒(7)/影杀(10)/虚空踏步(2) 虽继承 `AbstractAbility`，但重写了 `value()` 返回配置固定值（无敌时长/影杀固伤/跳跃倍率），同样不随里程碑成长；`countAtUnlock` 仅参与成长公式的差值计算。
>
> 指令后门（`/ap unlock ability`）解锁的被禁用能力不经过里程碑，数值经 `AbilityGate.effectiveCount` 平移（`count - grantedAt + countAtUnlock`：解锁时 = 基础值，之后正常成长）。所有能力数值调用必须走 `effectiveCount` 或 `value`，禁止直接 `ability.value(count)`。

### 觉醒机制（第 11 阶段）

全部里程碑达成并持有「冒险的终点」后，全部 30 种能力获得强化：

- **数值强化**：× `AWAKEN_MULTIPLIER`（1.5）或独立配置项，部分带硬上限钳制（如 `awaken_percent_cap` 默认 0.95，防完全无敌）
- **机制质变**：新增行为（御风冲刺、AOE 斩杀、威胁雷达等）

**激活链路**（`AdventureProgressCapability.activateFinalStageIfReady`，幂等）：`areAllMilestonesUnlocked()` 且未激活时 → `replaceBeginWithEnd`（冒险的开始 → 终点）→ `activateFullyUnlocked` → 计分板 + NBT 持久化 + 客户端同步。调用点：`grantMilestone` / `catchUpMissedMilestones` / **`/reload` 广播**（`MilestoneRegistry.onDatapackSync` 补跑——数据包缩小注册表 9/10→9/9 场景自愈；调用前经 `isAbilityUnlocked` 触发惰性缓存重建，防"删除了已解锁里程碑"的陈旧计数误激活）。恢复/补发路径（`giveAdventureBeginIfNeeded` / `recoverProgressFromItems`）在 fullyUnlocked 时自动把持有的「开始」升级替换为「终点」。

| 类型 | 能力 |
|------|------|
| **×1.5（钳制上限）** | 灵巧（钳 0.95）、大地之力（另 + 无视水中/空中惩罚）、不动如山（钳 100%）、无形之手、经验加成（×`awaken_xp_boost_mult`）、伤害抗性（钳 0.95）、加速（移速部分，另 + 疾跑推开） |
| **独立配置数值** | 休养生息（+5 HP）、磁吸（半径 ×1.5 + 吸经验球）、不朽装备（护甲 +2 / 武器 +25%）、鸿运当头（+2 等级）、禁疗之触（+ 易伤 ×1.2）、坚韧之躯（×1.5 向上取整）、受击坚韧（+6 层）、满载而归（取最大数量 + 每样 2 份）、翱翔（飞行速度 ×1.5）、淬魂之力（≤20% 斩杀 ×2.0）、拒绝篡改（30% 反弹）、旅者之力（审判范围 ×1.5 / 庇护可移动 30%） |
| **纯机制质变** | 虚空踏步（御风冲刺）、灵魂绑定（保经验）、全视之眼（威胁雷达）、环境免疫（免疫一切无实体来源伤害）、嗜血（过量吸血转护盾）、死亡抗拒（免费审判）、净魂（虚弱光环）、破敌之眼（禁无敌帧 3 秒）、恩赐永驻（正面无法驱散）、影杀（AOE 斩杀链）、真实血量（防秒杀底线 1 HP） |

## 共享基础设施

多能力共用的工具类，后文不再重复展开。

### HealthUtil - 血量反射工具（`util/HealthUtil.java`）

对抗外部模组篡改血量的核心武器库。原理：原版血量存储在 `SynchedEntityData`（实体同步数据）中，`getHealth()`/`setHealth()` 只是访问器——外部模组常用 Mixin/ASM 拦截访问器，但很难拦截对底层数据结构的直接读写。

| 方法 | 用途 |
|------|------|
| `getHealthDirect()` | 反射拿 `DATA_HEALTH_ID`（SRG `f_20961_`）直接从 `SynchedEntityData` 读真实血量，绕过 `getHealth()` 覆写 |
| `getEffectiveHealth()` | **架空参照读数**：`|getHealth() - getHealthDirect()| > 1.0` 判定原版血条被架空（重写 `setHealth/getHealth` 走自定义槽的 Boss，如亚波伦），返回 `getHealth()`（真实血量）；否则返回原版 DataItem 值（防 ASM 篡改 `getHealth()`）。敌方目标侧的血量基准/扣血检测统一走此方法（玩家侧防御仍用 `getHealthDirect` 防 ASM） |
| `setHealthDirect()` | 同理直接写入，绕过 `setHealth()` 覆写 |
| `setAllHealthLikeDirect()` | 写原版血量 + 通过 `scanCustomHealthKeys()` 扫描实体类继承链上所有 `EntityDataAccessor<Float>` 字段（带缓存），把自定义血量条目一并写入——对付把血存在自定义字段里的 Boss。**参照血量选择**：统一复用 `getEffectiveHealth()`（架空参照，与所有敌方目标侧读数判定同源）；**值范围约束**：Float 值需落在参照血量 10% 容差内（或差 ≤1.0）才认定为自定义血量 key，排除 `DATA_WATER_DAMAGE_SCALE` 等非血量 Float 误写 |
| `setAllHealthLikeRaw()` | 三步饱和写入：快照当前血量 -> `setAllHealthLikeDirect` -> 遍历 `SynchedEntityData.itemsById` 的所有 `DataItem`，对值≈快照值的条目**直接写 `DataItem.value` 字段**（Float/Double/Integer），完全不经过 `data.set()`，绕过 dirty 标记、监听器和一切 Mixin |
| `setHealthLikeAny()` | **分级直写统一入口**：① 通用层 `setHealthLikeGeneric`（扫描目标类含 "health" 的 `(float)` setter，调用后验证血量变化闭环）-> ② 插针层 `probeCapabilityHealth` -> ③ `setAllHealthLikeRaw`（DataItem 按值匹配兜底）。淬魂补刀/禁疗钳制/影杀归零统一走此入口 |
| `probeCapabilityHealth()` | **对象图插针**（v1.3.5 新增，详见共享基础设施下文）：`getHealth()` 被重定向/架空的 Boss（如亚波伦真血在 `FloatWrapped`、灵梦在 `CombatProgress.progress` 普通字段）在 DataItem 直写失效时，从实体递归遍历可达对象图，对每个 float 字段写测试值验证 `getHealth()` 联动后落笔。**按实体类缓存写入通路**（`WritePath`：字段 + 实体→宿主引用路径链，首次插针后 O(深度) 直达零全图搜索）；**写值前验证**：缓存命中时字段当前值须仍接近真血读数（同值域容差），路径漂移（同类多实例/索引错位）则缓存作废回退全图重探测——不盲写 |
| `zeroAllSynchedFloats()` | **全 float 同步数据保险丝**（砧板之刃[神]同款）：遍历目标所有 `DataItem`，float 类型一律字段直写归零——覆盖"不联动 `getHealth` 的隐藏 float 同步条目"（按值匹配/插针都够不到的旁路）。仅用于必杀场景（影杀饱和式秒杀），目标即将被删除副作用随实体消失；Player 守卫（饱食度/吸收等 float 条目属误伤） |
| `clearNegativeFloatDeltas()` | 把 DataItem 中所有负值 Float 归零，反制外部注入"负血量偏移量"再 ASM 篡改 `getHealth()` 叠加的手法。**仅供 TrueHealth 防御侧调用，攻击侧不用** |
| `restoreFoodData()` | 反射直写 `FoodData.foodLevel`（`f_38696_`）= 20、`saturationLevel`（`f_38697_`）= 20，绕过 `setFoodLevel()` 拦截 |
| `removeDirect()` / `setRemovedDirect()` / `setRemovedFieldDirect()` | 三种强度的实体移除：反射调 `remove()` -> 反射调 private `setRemoved()`（不参与虚分派）-> 直接写 `Entity.removalReason` 字段（`f_146795_`） |
| `writeRemovalReasonDirect()` | `setRemovedFieldDirect` 的泛化版本（参数 `Entity` 而非 `LivingEntity`），供非 LivingEntity（如 `EnderDragonPart`）复用同一字段直写 |
| `clearRemovedFlag()` | 写 `null` 到 `removalReason`，把被外部标记移除的玩家"复活" |
| `eradicateFromWorld()` | 从 Minecraft 内部 7 个实体追踪结构直接抹除实体——`EntityLookup.byId/byUuid`、`knownUuids`、`EntityTickList`（active/passive）、`EntitySection`（allInstances + per-class byClass）、`ServerChunkCache.removeEntity`、龙部件 `dragonParts`（详见[影杀](#影杀-shadow_kill)） |
| `HURT_DEPTH` | `ThreadLocal<Integer>` 计数器：`hurt()` 调用链深度（`RejectHealthManipMixin` HEAD +1 / RETURN -1），区分"合法 hurt 内 setHealth"与"外部直调 setHealth"；ServerTickEnd 无条件归零（hurt 不跨 tick，tick 末深度必为 0），防御外部模组 cancel `hurt()` 导致的深度残留 |
| `INTERNAL_HEALTH_WRITE` | `ThreadLocal<Boolean>`：模组内部降血标记（坚韧之躯启用/关闭时的血量裁剪在 `setHealth` 调用窗口置 true，try/finally 配对）。`RejectHealthManipMixin` / `DeathDefyMixin` / `TrueHealthMixin` 三个 setHealth 拦截点均放行——防的是外部篡改，不拦模组自身状态维护；TrueHealth 同步备份也放行（否则 backup 冻结旧值、下次 getHealth 把裁剪反向修复）。**新增内部降血 `setHealth` 调用必须包此标记** |
| 玩家实体特殊处理 | ① `scanCustomHealthKeys` 类层次遍历跳过 `Player.class` 声明的字段（饱食度/吸收与血量同量级，值域容差无法区分，不排除会误缓存为"自定义血量"）；② `setAllHealthLikeRaw` 步骤③（值匹配兜底遍历 DataItem）对玩家目标整体跳过（玩家血量维度只有 `DATA_HEALTH_ID`，遍历只会误写饱食度/吸收/等级同步副本） |

### 对象图插针（`probeCapabilityHealth` / `probeGraph`）

通用"找真血"体系——不依赖任何模组 API/包名，纯对象图遍历 + 验证闭环：

- **门禁 `probeDataItemLinked()`**：直写 `DATA_HEALTH_ID` 槽 value = 原值-1（绕过 `set()` 直改 `DataItem.value` 字段），观察 `getHealth()` 是否联动。联动 = 正常实体（`getHealth` 真读槽 9）-> DataItem 直写足够，跳过插针（性能门禁）；不联动 = `getHealth()` 被重定向/架空（如亚波伦 ASM 改写读 `MegaCapability`）-> 进插针层。扰动同 tick 内 finally 还原，客户端无感知
- **插针 `probeGraph()`**：从实体自身递归全部可达对象（visited 防环 + 深度上限 10 + 世界/注册表全局巨对象跳过），对每个 float/Float 字段：值域过滤（候选须接近 `getHealth()` 真血读数，±20% 容差）-> 写 原值-1 小扰动 -> **双重判据**（写入前后 `getHealth()` 必须真实变化 ≥0.5 + 变化指向测试值 ±1.0）-> 命中即写目标值。正常实体即使被插也无副作用（扰动立即还原，只有"写它 getHealth 就变"的真血字段才落笔）
- **路径缓存 `WritePath`**：命中后缓存（字段 + 实体→宿主引用路径链），后续同类实体直写 O(深度) 直达宿主，不再全图搜索（弹幕 Boss 大对象图不卡）。**写值前验证**：字段当前值仍须接近真血读数，路径漂移（同类多实例/Collection 索引错位）则缓存作废、回退全图插针重探测——杜绝盲写错误宿主
- 覆盖范围：普通字段真血（亚波伦 `FloatWrapped#value`、灵梦 `CombatProgress#progress`——均不在 SynchedEntityData 里，`setAllHealthLikeRaw` 值匹配与 `zeroAllSynchedFloats` 都够不到，唯有插针能摸到）

### 其余工具类

- **InvulClearUtil**：`clearCustomInvulTimers()` 遍历实体继承链字段，按命名模式反射清除模组 Boss 的自定义无敌——`int` 字段名含 `invul` -> 置 0、`boolean` 含 `invul` -> 置 false、`boolean` 含 `vulnerable` 且不含 `invul` -> 置 true（Java `contains` 大小写敏感，显式覆盖大写开头变体）
- **FriendlyFireProtection**：`isOwnerTarget()`——目标是 `TamableAnimal` 且主人是攻击者本人时返回 true。所有"超模"进攻能力（淬魂/影杀/破敌/审判/嗜血）生效前都先过这个检查，不误伤自己的驯服生物
- **FortuneContext**：两个 `ThreadLocal`（`CURRENT_BREAKER`/`AWAKENED`）桥接"Mixin 注入点参数里没有玩家引用"的问题（详见[鸿运当头](#鸿运当头-fortune_favor)）
- **AbilityGate**：`isAbilityActive`/`getActiveProgress`/`isActive` 门禁断言 + `value` 数值取值（`Optional<Float>`）+ `awakenedRatio`/`awakenedPercent` 觉醒倍率（含 cap 钳制）+ `effectiveCount` 指令解锁数值平移
- **AbilityIds**：30 个能力 ID 常量集中管理，代码侧调用统一引用，typo 从「运行时静默失效」降为「编译可查」
- **ProgressCache**：以实体为弱 key 缓存「本 tick 已解析的 progress 引用」（tick 变化失效重算），供 `getHealth`/`getAttribute`/`setHealth` 等 MC 极高频调用点使用——缓存的是引用而非门禁结果，无延迟；弱 key 防泄漏

### NetworkHandler - 网络层

`network/NetworkHandler.java` 注册 8 个网络包（所有 C2S 处理均带方向校验 + 服务端门禁）：

| 包 | 方向 | 用途 |
|----|------|------|
| `AdventureSyncPacket` | S2C | 同步 Capability 数据（含里程碑注册表元数据），`SyncUtil.syncToClient` 发送 |
| `AdventureSyncRequestPacket` | C2S | 客户端登录/重连时请求同步 |
| `DoubleJumpPacket` | C2S | 二段跳（服务端校验门禁后施力） |
| `AbilityTogglePacket` | C2S | 能力面板开关（服务端持久化） |
| `BuffTogglePacket` | C2S | Buff永驻标签开关（恩赐永驻黑名单） |
| `BuffBlacklistSyncPacket` | 双向 | 黑名单同步（C2S 上报，S2C 广播更新） |
| `ActiveSkillPacket` | C2S | 释放主动技能（skillIndex，服务端重校验） |
| `SkillSwitchPacket` | C2S | 切换主动技能（服务端持久化并回同步，切换状态不被任意 sync 覆盖重置） |

**加固**：`BuffBlacklistSyncPacket` decode 长度限制（C2S 请求 128 / S2C 广播 2048，防恶意 OOM）；`AdventureSyncRequestPacket` 按全局 tick 节流（防刷包风暴）；`AbilityTogglePacket`/`SkillSwitchPacket` 各加 per-player 5 tick 限频（每次操作都回发全量同步，防恶意刷包放大流量；250ms 内双击可能被吞一次，下次 sync 自愈）；`BuffTogglePacket` 校验恩赐永驻能力门禁 + effectId 注册验证。

## 里程碑 2 · 初尝败绩

### 虚空踏步 `void_step`

**效果**：空中可再次跳跃（二段跳），清空摔落距离。觉醒「御风」：疾跑时二段跳朝视角方向水平冲刺，松开疾跑为纯垂直跳。

**实现**（客户端预测 + 服务端权威，两端共用 `VoidStepMovement` 施力公式）：
1. **客户端**（`JumpInputHandler`，钩子 `MovementInputUpdateEvent`，与原版跳跃同 tick 生效）：边沿检测 `input.jumping`（按一下跳一次）；本地维护 `clientJumpsUsed`（空中仅 1 次，落地清零）；条件满足时调 `VoidStepMovement.applyJump(player, power, dash)` 做即时预测（`dash = 觉醒 && 疾跑`），发送 `DoubleJumpPacket`
2. **服务端**（`DoubleJumpHandler.handleDoubleJump`）：重新校验门禁（不骑乘/不在水中/不在飞行；**刻意不校验 onGround**——客户端已在 !onGround 时才发包，服务端再校会因网络延迟误杀）；`AIR_JUMPED` 集合记录本空中周期已跳（落地清零由 tick 检测 onGround 完成），每周期仅 1 次；鞘翅滑翔/攀爬不触发（客户端与服务端条件对称）
3. 施力：`0.42 × 方块 JumpFactor + 跳跃提升加成`，整体 × `void_step_power`（1.2）；Y **直接覆盖**（对齐原版 `jumpFromGround`）；`fallDistance = 0`；**保留当前水平动量**（跑得快跳得远）；成功不发包（信任客户端预测，两端同公式无顿挫），拒绝时才发 `ClientboundSetEntityMotionPacket` 拉回防独飞——**落地瞬间的拒绝（落地竞态：服务端 `AIR_JUMPED` 在 tick END 清零、客户端已先清零）不发拉回包**（客户端位置已随落地自然收敛，拉回只会制造顿挫）；空中拒绝仍拉回
4. 服务端施力**只设 Y 不施加御风冲刺**——水平冲刺由客户端预测（位置客户端权威），避免两端 sprint 状态不同步导致水平跳变
5. 生命周期：登出/死亡重生（Clone）/落地清理 `AIR_JUMPED`；客户端在死亡重生/换维度（玩家引用变化）时重置 `clientJumpsUsed`/`wasJumpDown`，防旧玩家状态残留
- 觉醒「御风」：`dash = 觉醒 && isSprinting()`，疾跑时朝 `YRot` 施加水平冲刺（`awaken_void_step_dash` 0.6，冲量随当前移速加成——跑得快冲得远，与加速能力联动），松开疾跑纯垂直跳

配置：`void_step_power`(1.2) / `awaken_void_step_dash`(0.6)

**效果**：脱离战斗 5 秒后，每 3 秒自动回血并回满饱食度；**饱食度满时仍可进食**（v1.3.7，兼容农夫乐事等通过进食成长的模组）。回量随里程碑成长；觉醒每周期额外 +5 HP。

- 觉醒：`amplifier += awaken_rapid_recovery_bonus`（5）

配置：`rapid_recovery_amplifier_base`(0) / `rapid_recovery_amplifier_step`(1) / `rapid_recovery_delay_ticks`(100) / `rapid_recovery_check_interval`(60) / `rapid_recovery_heal_per_amplifier`(1.0) / `rapid_recovery_allow_eat_at_full`(true) / `awaken_rapid_recovery_bonus`(5)

### 灵魂绑定 `soul_bind`

**效果**：死亡时保留正面药水效果；觉醒时额外保留经验（不掉落）。

**实现**（利用 persistentData 跨越死亡——Capability 在死亡时会被 `invalidateCaps`）：
- **死亡时**（`LivingDeathEvent` @**LOWEST**，入口显式 `if (event.isCanceled()) return;`——Forge 对非 receiveCanceled 监听器在事件被取消时**直接跳过调用**（不执行本方法），该守卫为防御性冗余；LOWEST 使本监听器相对其他 LOW/NORMAL 监听器更晚执行——读取经验的第三方监听器先于清零执行，语义更优）：**只序列化正面效果**（`BENEFICIAL`，负面随死亡清除）为 `CompoundTag` 存入 `player.getPersistentData()`（键 `AP_SoulBind_Buffs`）；经验以三字段（`level`/`progress`/`total`）存入 `AP_SoulBind_Exp`
- **经验清零**（仅觉醒）：备份经验后清零 `experienceLevel`/`experienceProgress`/`totalExperience`——清零后死亡不会喷出经验球；非觉醒不备份也不清零，经验照常掉落捡回（原版行为）
- **重生时**（`PlayerEvent.Clone`，`isWasDeath()` 分支）：从 `event.getOriginal()` 的 persistentData 读回，逐个 `MobEffectInstance.load()` + `addEffect()`；经验**直接赋值三字段 + 发 `ClientboundSetExperiencePacket` 同步**（避免 `giveExperiencePoints` 的 `increaseScore` 副作用与 level 重算偏差），随后删除两个键防重复恢复
- 非死亡 Clone（维度切换）：**防御性清理**死亡写入但未消费的残留键；经验由原版 `restoreFrom` 复制，buff 由原版保留

### 禁疗之触 `healing_block`

**效果**：攻击为目标施加 3 → 6 秒"禁疗之触"标记：期间禁止一切治疗、禁止不死图腾、血量只能降不能升，标记期间死亡无法被取消。觉醒禁疗 + 易伤 20%；淬魂之力对标记中的目标伤害 ×1.5。**PVP 无效**（禁疗标记含 FORCE_KILL 强制击杀链，击穿玩家自身死亡抗拒/真实血量防御属行为自冲突）。

**实现**：入口 `LivingHurtEvent` -> `CombatAbilityHandler.handleHealingBlock()` -> `HealingBlockEffect.apply(target, ticks)`。`HealingBlockEffect` 名义上是 `MobEffect`（暗红色图标仅作视觉指示，注册名 `healing_block`），**真实判定依据是 NBT 标记 + 内存追踪表双源**：NBT 标记 `MME_UndyingSlashEndTime`（`persistentData`，防止效果被 `removeAllEffects` 清掉后禁疗失效，重启后可恢复；**持久化 NBT key 保留旧名 `UndyingSlash` 防存档丢失**）；内存表（UUID -> 血量低点 + 到期时间）用于兜底——部分 Boss（如启示录亚波伦 `Apostle`）重写 `getPersistentData()` 每次返回全新空 tag，NBT 标记写入即丢、读取永远为空，此时 `isActive()` 回退查内存表，钳制链不因 NBT 失效（代价：此类实体重启后标记丢失）。**实体 join 时从 NBT 回填内存表**（`EntityJoinLevelEvent`：`endTime > gameTime` 才回填，`TRACKED_HEALTH` 用 `putIfAbsent` 保留内存中更低的钳制线、`VULN_END` 直接覆盖——区块卸载 2-tick 宽限清理后重载，钳制链与觉醒易伤恢复生效；重写 `getPersistentData` 的实体无回填源，属已知限制）。五层拦截（源头拒绝 + 事后钳制 + 双通道同步）：

1. **事件层**（`HealingBlockEffect.EventHandler`）：
   - `LivingHealEvent` -> cancel（禁一切治疗）；`LivingUseTotemEvent` -> cancel（禁图腾）
   - `LivingTickEvent`：仅过期清理（钳制由 Mixin tick TAIL 覆盖）；全链路用 `getEffectiveHealth`（架空参照，自定义血条 Boss 取真实血量，普通实体回落 `getHealthDirect` 防 ASM 改写 getHealth）
   - `LivingDeathEvent` @HIGHEST：写 `MME_UndyingSlash_ForceKill` 标记；@LOWEST：若死亡事件被其他模组 cancel 且存在 ForceKill 标记，强制 `setAllHealthLikeRaw(entity, 0)` + `setCanceled(false)`——**死亡锁定**（两处监听均 `receiveCanceled=true`，确保被其他模组 cancel 后仍能触发 uncancel）；@LOWEST 分支无论是否触发 ForceKill 都清除跟踪数据与 NBT 标记，防止复活后残留禁疗
   - `ServerTickEvent`(END)：对所有被追踪实体做最终钳制，覆盖完全不调 `setHealth()` 的 Boss；2 tick 宽限期容忍跨维度传送
2. **Mixin 跟踪层**（`HealingBlockMixin`，`setHealth` @RETURN）：记录每次合法降血后的新低水位
3. **Mixin 钳制层**（`tick` @TAIL）：AI/回血/事件全部跑完后最后检查一次，高于低水位即直写钳回
4. **源头拦截层**（`HealingBlockMixin`，`setHealth` @HEAD cancellable）：禁疗中且 `newHealth > tracked`（回血请求）直接取消 + `setHealthLikeAny` 直写真血低点——**从"事后钳制"升级为"源头拒绝"**，回血请求不落地、网络同步不产生，Boss 自定义血条（灵梦 `CombatProgress`）不再"回满→被钳回"乱跳
5. **clampBack 双通道**：钳制时 `setHealthLikeAny`（插针直写真血，覆盖普通字段真血）+ `self.setHealth(tracked)`（走完整覆写链触发 Boss 自定义血条的网络同步包）双写——只直写字段不 set 时，走自定义同步的 Boss（灵梦 `CombatToClient` 网络包）客户端血条不更新；`onServerTickEnd` 终极钳制同走 clampBack

配置：`healing_block_base`(3) / `healing_block_per_milestone`(1) / `awaken_healing_block_vuln`(1.2) / `soul_quench_healing_block_multiplier`(1.5)

### 翱翔 `soar`

**效果**：获得创造模式飞行；觉醒飞行速度 ×1.5。

**实现**（核心难点：与其他模组的飞行来源共存）：
- 入口：每 tick 对账（`PlayerStateHandler.onTick`）授予：`abilities.mayfly = true` + `onUpdateAbilities()`，同时在 Capability 记 **`soarGrantedFlight = true`**——"这个 mayfly 是翱翔给的"（`grantMilestone()` 解锁即时授予与开局安全网两条路径不置标记，依赖下一 tick onTick 补标记）

- 飞行速度写 `flyingSpeed` 字段，只在与目标值偏差 > 0.0001 时写入——防止每 tick 重复乘法导致速度指数爆炸；**仅觉醒时覆盖**（觉醒倍率写入后补 `onUpdateAbilities()` 同步客户端——`setFlyingSpeed` 不会自动发包，客户端 LocalPlayer 保持旧速度直到下次 abilities 同步）；非觉醒保持原版 0.05，不覆盖其他模组对 flyingSpeed 的设定
- 时序处理：`Clone` 跨维度保留飞行中状态；`PlayerChangeGameModeEvent` 立即重新授予（玩家在空中时自动设 `flying=true` 防坠落，地面保留双击空格触发）；`grantMilestone()` 解锁时立即同步（不等下一 tick，消除竞态）

### 破敌之眼 `piercing_gaze`

**效果**：攻击无视一切无敌——原版无敌帧、模组 Boss 的自定义无敌、限伤、"必须先破条件才能打"的机制统统穿透。觉醒后破无敌一击，目标 3 秒内无法获得无敌帧。

**实现**：模组内最复杂的拦截体系，4 层纵深防御分布在 3 个 Mixin + 1 个事件 Handler + 1 个公共结算工具。核心思路：**Boss 的"无敌"实现五花八门，每层针对一类实现**；公共门禁（`PiercingGazeUtil.shouldPierce`：攻击者持有能力 + 非友伤 + 非玩家目标 PVP 禁用）与穿透结算（postHurtEvent / invokeActuallyHurt / afterPierceFallback）统一收口在 `PiercingGazeUtil`，三注入点共用。

| 层 | 位置 | 针对的无敌实现 |
|----|------|---------------|
| **Layer 0** | `PiercingGazePlayerAttackMixin`：`@Redirect` 替换 `Player.attack()`（`m_5706_`）内部的 `target.hurt()` 调用 | 完全重写 `hurt()` 且不调 `super.hurt()` 的 Boss（如暮色森林巫妖）——此时 Layer 2 的注入点根本不会执行。`@At` target owner 为 `Entity`（匹配 INVOKEVIRTUAL owner）+ handler 参数为 `Entity`（`instanceof LivingEntity` 转型）+ **血量比对**（`getEffectiveHealth` 架空参照读真实血量——自定义血条 Boss 原版槽架空时用 `getHealthDirect` 会误判"未扣血"而恒走穿透，实际扣血才放行，覆盖"普攻原版怪/调 super 扣血但 return false/Boss 假成功拦截"三类）。未扣血且 `shouldPierce` 通过时手动 post `LivingHurtEvent` 再经 Accessor 直调 `actuallyHurt()`。**事件已发判定**：`beginVanillaHurtScope` 记录 post 计数基线（调 `target.hurt()` 前），扣血成功后 `consumeVanillaHurtEventPosted` 按**目标实体**比较增量（per-entity——嵌套实体的事件不误判，如 fantasy_ending 等 ASM 跳过 ForgeHooks 的环境无新增 post 才补发）——正常环境原版已 post，不重复补发（防淬魂/嗜血/禁疗同 tick 双倍结算）。**风暴守卫**：穿透三连前 `IN_PIERCING.set(true)`、`finally` 恢复旧值（post 期间第三方监听器递归 hurt 时递归层跳过穿透；恢复旧值而非硬置 false——本层 post 嵌套在外层 Layer 2 情况 A 的监听器链内时不清掉外层守卫） |

### 影杀 `shadow_kill`

**效果**：为攻击目标投影一条"影子血量"（紫色 Boss 栏显示，多人各自独立）。每次攻击削减 `4 + 目标总血量 4%`，与目标真实血量无关——**无论 Boss 怎么回血、锁血、免疫，影子血量只减不增，归零即斩杀**。觉醒后斩杀触发 8 格 AOE，削减周围怪物 15% 影子血量并可连锁斩杀。PVP 无效。

**实现**：
- 入口：`LivingHurtEvent` -> `CombatAbilityHandler.handleShadowKill()`，同 tick 去重（key 为 (attacker, target) 复合——多人同 tick 攻击同一目标各削各的，只防同一攻击者的重复结算）
- **影子血量存在攻击者（玩家）侧的 `persistentData`**（`AP_ShadowHP_Data` -> `{目标UUID: {totalHP, shadowHP, endTime}}`）而非目标侧——Boss 无法通过阶段切换、NBT 清理或任何自身手段逃脱。`totalHP` 在首次攻击时快照，防止后续 maxHealth 变化污染计算；维度切换（非死亡 Clone）时数据随玩家转移，跨维度战斗进度保留；死亡清零为刻意设计（重生后重新积累）；玩家死亡重生/换维度时清理其 BossBar（防旧实例重复广播）
- 条目 5 分钟不攻击自动过期（懒清理 + 每 200 tick 全局清理 + 目标死亡/玩家登出清理，含 BossBar 引用防泄漏）；onServerTick 检测 target 有效性（死亡/卸载/换实体后 **2 个清理周期宽限**清理 shadowData + BossBar——计数单位是清理周期而非 tick，`SHADOW_KILL_CLEANUP_INTERVAL` × 2 = 默认 400 tick；防 fantasy_ending 等 ASM 改 die 不走 LivingDeathEvent 导致 BossBar 残留）——**缺失计数按 (attacker, target) 复合 key 独立**（多人同打一目标时各攻击者独立计数，不再同周期叠加把"1 周期缺失"误判为"2 周期"误清影子血量）；玩家登出时顺带清理其影子数据对应的缺失计数条目
- BossBar 采用双层 Map（`attackerUUID -> targetUUID -> ServerBossEvent`）：多人同打一 Boss 各有独立 BossBar 显示各自影子血量（数值走翻译键 `ability.adventure_power.shadow_kill.bar` 的"当前/总量"格式），互不干扰；玩家登出时按攻击者维度整体移除

**斩杀链**（`executeShadowKill`，`KILLING` Set 防重入）：
1. 清 `hurtTime`/`invulnerableTime` 后 `target.hurt(killSource, target.getMaxHealth() * 10F)`——`killSource` 为内部伤害类型 `adventure_power:shadow_kill`（新增 damage_type JSON + 4 个 bypasses 标签：斩杀伤害不再触发嗜血吸血/淬魂追加/影杀递归削减；死亡消息走 `death.attack.shadow_kill` 翻译键；无敌目标现在也能被影杀斩杀）。`Float.MAX_VALUE` 在某些模组的 `amount × ratio` 计算中会溢出为 Infinity/NaN 导致卡死，`maxHealth × 10` 足够秒杀且不溢出
2. 目标还活着（hurt 被完全拦截）-> `saturationKill()` 饱和式处决：
   - **① 插针归零**：`setHealthLikeAny(target, 0)` 三级链（setter 扫描 → 对象图插针 → DataItem 按值匹配）直写真血归零——覆盖普通字段真血（亚波伦 `FloatWrapped`/灵梦 `CombatProgress`）
   - **①b 全 float 保险丝**：`zeroAllSynchedFloats(target)` 清空所有 float 同步条目——覆盖"不联动 `getHealth` 的隐藏 float 条目"（插针够不到的旁路），砧板之刃[神]同款
   - 强制掉落装备 + 反射调 `dropAllDeathLoot()`（`m_6668_`）+ 手动 post `LivingDeathEvent`——**战利品不因非常规死亡而丢失**（FTB Quests 等任务模组可正常记录击杀）
   - **五重移除**：`remove(KILLED)` -> `remove(DISCARDED)` -> 反射 `removeDirect` -> 字段直写 `setRemovedFieldDirect` -> `setRemovedDirect(CHANGED_DIMENSION)`（部分 Boss 的 Mixin 只拦 KILLED/DISCARDED，不拦"换维度"）
   - 发 `ClientboundRemoveEntitiesPacket` 强制客户端消失
   - **`eradicateFromWorld()`**：反射从 Minecraft 内部 7 个实体追踪结构直接抹除——`EntityLookup.byId`、`EntityLookup.byUuid`、`PersistentEntitySectionManager.knownUuids`、`EntityTickList`（active/passive）、`EntitySection.classInstanceMultiMap`（allInstances + per-class byClass 分列表）、`ServerChunkCache.removeEntity`、**龙部件 `dragonParts`**（末影龙被秒杀时 part 不走原版死亡流程，按 `part.getId()` 从 `Int2ObjectMap` 摘除并直写 removalReason，防止 part 持续引用死龙）。全程 `Field.get` + 集合 `remove()`，不调用任何实体方法，**外部 Mixin 无从拦截**
   - **⑨ 最终确认**：`!target.isRemoved()` 时兜底重写 `removalReason = KILLED`（防防护 Boss 在移除链中清除标记的极端场景）+ DebugLog 输出终态
- 觉醒 AOE（`shadowKillAoe`）：斩杀后对半径 8 格内至多 16 个 `Monster` 各削减 `totalHP × 15%` 影子血量，归零者递归进入斩杀链；**未归零的目标会写入攻击者影子数据新建追踪条目**（新条目按当前 maxHealth 快照，已有条目保留原 totalHP 快照），后续可继续削减——"可连锁斩杀"的可持续性基础

配置：`shadow_kill_flat_damage`(4) / `shadow_kill_hp_ratio`(0.04) / `shadow_kill_data_expire_ticks`(6000) / `awaken_shadow_kill_aoe_radius`(8.0) / `awaken_shadow_kill_aoe_ratio`(0.15) / `awaken_shadow_kill_aoe_max_targets`(16) / `shadow_kill_cleanup_interval`(200)

### 真实血量 `true_health`

**效果**：把玩家血量备份到 Capability，任何绕过正常伤害流程的血量篡改（直写数据、假死标记、强制 die、注入负值偏移）都会被检测并自动修复；觉醒后非伤害路径的致死写入强制保留 1 HP。

**实现**（`TrueHealthMixin`，5 个注入点组成四层防护）：

| 注入点 | SRG | 职责 |
|--------|-----|------|
| `getHealth()` @HEAD | `m_21223_` | **读取层**：从 Capability 备份返回真实血量，绕过被污染的 SynchedEntityData；检测 DataItem 与备份偏差，非法降血直写则 `setAllHealthLikeRaw` 修复；假死（DataItem ≤ 0 但备份 > 0）也修复；**备份污染自愈**——备份为 NaN/Infinity（外部字段直写 Capability 备份字段，合法路径备份恒为正常 float）时从 DataItem 重建；rawHealth 异常时的 restore 选值强制 `isFinite`（防 backup=+Inf 与 DataItem 同时非法时把玩家血量永久修复成 Infinity） |
| `setHealth()` @RETURN | `m_21153_` | **同步层**：只在合法路径更新备份——`HURT_DEPTH > 0`（hurt 调用链内）或回血时同步；外部直调降血**拒绝同步**。觉醒防秒杀底线：非 hurt 路径写入致死值时强制保留 1HP（正常 hurt 打死不受影响） |
| `isDeadOrDying()` @HEAD | `m_21224_` | 备份 > 0 时强制返回 false，反假死 |
| `die()` @HEAD | `m_6667_` | 备份 > 0 时取消，拦截不经 hurt/setHealth 直接调 `die()` 的秒杀 |
| `tick()` @HEAD | `m_8119_` | **存活性自检**：每 tick 检查 `isRemoved()`/零血/死亡标记但备份 > 0 -> `clearRemovedFlag()` + 修复，最后兜底。**备份 NaN/Inf 时先重建再检测**（镜像读取层重建逻辑，保住 isRemoved 救援——直接跳过会让被标记移除的玩家无人清除 removalReason）；DataItem 也非法（双重污染）才放弃自检 |

- 修复动作 `repairHealth()` = `setAllHealthLikeRaw(备份值)` + `clearNegativeFloatDeltas()`（清掉外部注入的负值 Float 偏移条目）
- `IN_ON_GET_HEALTH` ThreadLocal 防修复过程中递归触发 `getHealth`——**重入分支直接返回备份或最大生命，不再调 `getHealthDirect`**（其退化路径（反射初始化失败）会回落到 `getHealth()` 再次进入本注入点，backup ≤ 0 时形成无限递归）；重入分支同样强制 `isFinite`（backup=+Inf 不当作有效备份返回）
- **备份初始化**：备份值 ≤ 0 时从当前 DataItem 同步初始化（重生后恢复场景）
- **觉醒容差加倍**：觉醒时偏差判定容忍 `EPSILON × 2`（±0.002 内的微小降血不触发修复，避免与觉醒禁疗等高频小幅度直写打架）
- **事件层兜底**（`TrueHealthHandler`）：`LivingDeathEvent` @HIGH 在备份 > 0 时 cancel——`die()` Mixin 被外部 ASM 绕过时（Mixin 注入点失效）的最后防线
- "合法降血"的判定依赖拒绝篡改能力维护的 `HURT_DEPTH` 标记；`HURT_DEPTH` 由 ServerTickEnd 无条件归零兜底（外部模组 cancel `hurt()` 导致的深度永久残留不再使保护失效）

配置：`debug_log`(false，全局调试总开关) / `debug_log_true_health`(false，真实血量子开关，位于「冒险能力配置 > 调试」分组；v1.3.6 起取代旧键 `true_health_debug_log`)

### 拒绝篡改 `reject_manip`

**效果**：拦截外部模组对玩家血量的非法直接修改（不经过伤害流程的 `setHealth` 降血）和 maxHealth 恶意压低；觉醒后把被拦截的降血量按 30% 反弹给最后攻击者。

**实现**（与真实血量分工：本能力拦"写入"，真实血量修"已写入"）：
- **HURT_DEPTH 标记**（`RejectHealthManipMixin`）：`hurt()`（`m_6469_`）@HEAD 时 ThreadLocal 计数 +1，@RETURN 时 -1，区分"hurt 内部的合法 setHealth"与"外部直调 setHealth"。服务端主线程单线程，ThreadLocal 天然隔离调用链，无锁无查表。外部模组以低优先级 Mixin cancel `hurt()` 时 RETURN 不执行、深度残留 +1——`HealthUtil.resetHurtDepthPerTick()` 在 ServerTickEnd 无条件归零（hurt 不跨 tick，tick 末深度必为 0 是不变量），泄漏窗口仅为 cancel 发生的同 tick 内
- **setHealth 拦截**（`m_21153_` @HEAD）：NaN/Infinity 直接 cancel；回血放行；`HURT_DEPTH > 0` 放行；其余（外部直调降血）-> `ci.cancel()`
- **maxHealth 底线**（`RejectHealthManipAttributeMixin`，`AttributeInstance.setBaseValue()`（`m_22100_`）@HEAD）：新值 < 6.0（3 颗心）时先 O(1) 查 `ATTR_OWNER` 映射找所有者，未命中（getAttribute 未被调用的早期路径）再 fallback 遍历在线玩家并补登记。是受保护玩家则 cancel
- 共享的 `ATTR_OWNER` Map 放在 `RejectHealthManipUtil` 工具类（Mixin 类禁止非 private static 成员）；登记注入点：`getAttribute`（`m_21051_`）@RETURN 时对冒险者/觉醒玩家登记"AttributeInstance -> 所有者"；`remove()`（`m_142687_`）@HEAD 注入 `cleanupOnRemoval`，实体卸载时从 `ATTR_OWNER` 移除其映射，防内存泄漏
- 觉醒反弹：`(当前血量 - 目标写入值) × 30%` 以魔法伤害反弹给 `getLastHurtByMob()`

配置：`awaken_reject_manip_reflect_ratio`(0.30)

### 旅者之力 `active_skill`

**效果**：解锁两个主动技能（Y 切换 / G 释放，共享 0.5 秒 GCD）：
- **旅者审判**（30 秒 CD）：对周围 6 格敌对生物造成 `10 + (最大生命 + 当前生命) × 3% × 里程碑数` 的范围伤害；觉醒范围 ×1.5（9 格）
- **旅者庇护**（90 秒 CD）：5 秒无敌 + 清负面 + 灭火；觉醒后庇护期间可 30% 速度移动

**实现**：
- 链路：客户端 `InputHandler`（Y 键切换 / G 键释放，本地预检 GCD/CD 减少无效包）-> `SkillSwitchPacket`（Y 键切换由服务端持久化并回同步，切换状态不被任意 sync 覆盖重置；服务端拒绝时也回发同步让客户端乐观更新回滚）-> `ActiveSkillPacket` -> 服务端 `ActiveSkillHandler.handleSkillRelease()` **重新完整校验**（skillIndex 范围、`isFullyUnlocked`、能力启用、GCD、各技能 CD——防御性自门禁）
- **审判**（`executeJudgment`）：自定义伤害类型 `adventure_power:judgment`；排除玩家/驯服生物，其余都打（覆盖史莱姆/幻翼等非 Monster）；血量判断改用 `getEffectiveHealth`（架空参照，防 ASM + 自定义血条 Boss 正确读数）；带与淬魂相同的**直写补刀**（实际伤害不足 -> `setAllHealthLikeRaw` 修正，归零强制 `die()`）；补刀时同时重置 `invulnerableTime = 0`、`setLastHurtByMob/Player`、反射置 `deathScore = -1`（防 `die()` 内部重复击杀计分）
- **庇护**：
  - 写 Capability 的 `sanctuaryInvulEnd`，过期由 tick 处理清零并同步
  - `PlayerStateHandler.onSanctuaryDamage`（`LivingAttackEvent` @HIGHEST）在无敌期内 `event.setCanceled(true)`，但 `DamageTypeTags.BYPASSES_INVULNERABILITY`（`/kill`、虚空等）**照常放行**，防止玩家用庇护规避管理员指令或掉出世界
  - **非觉醒**期间移动速度锁 0（完全定住不能走），**觉醒**才允许 `awaken_sanctuary_speed`（0.3）倍减速移动；庇护结束时恢复原始移动速度（记录 `ORIGINAL_MOVE_SPEED`，不硬编码 0.1，不覆盖其他模组修改）；无记录时做**残留判定**——服务端重启后 Map 清空、player.dat 已落盘庇护目标值（0/0.03），若当前 baseValue ≈ 模组庇护目标值则回归原版 0.1，否则视为其他模组修改不覆盖
  - `event.isCanceled()` 前置检查，避免重复拦截其他能力已取消的事件
- 冷却全部存 Capability（NBT 持久化，重登不重置），释放后 `syncToClient` 驱动 HUD（`ActiveSkillHudOverlay`）显示冷却环
- 觉醒联动：死亡抗拒触发时直调 `executeJudgment()`，绕过 CD 和 GCD（免费审判）

配置：`active_skill_judgment_base_damage`(10.0) / `active_skill_judgment_hp_ratio`(0.03) / `active_skill_judgment_radius`(6.0) / `active_skill_judgment_cooldown`(600) / `active_skill_sanctuary_duration`(100) / `active_skill_sanctuary_cooldown`(1800) / `active_skill_gcd`(10) / `awaken_judgment_range_mult`(1.5) / `awaken_sanctuary_speed`(0.3)

## 附录：能力联动关系

- **虚空踏步 × 加速**：御风冲刺冲量随当前移速加成，跑得快冲得远
- **淬魂之力 × 禁疗之触**：对禁疗标记中目标伤害 ×1.5
- **死亡抗拒 × 旅者之力**：觉醒触发时免费释放一次审判（不耗 CD、不占 GCD）
- **真实血量 × 拒绝篡改**：拒绝篡改拦「写入」（setHealth 拦截），真实血量修「已写入」（getHealth 时检测修复），共享 `HURT_DEPTH` 标记判定合法伤害
- **破敌之眼 × 影杀/嗜血等监听器**：Layer 0 放行时手动补 post `LivingHurtEvent`，被 ASM 改 hurt 的模组跳过原版事件时监听器仍能触发（事件已发标记防重复补发）
- **嗜血 × 伤害抗性**：嗜血 @LOW 基于减伤后最终金额吸血，顺序无歧义
- **影杀/淬魂/审判 × 嗜血**：内部伤害源（`soul_strike`/`judgment`/`shadow_kill`）不触发二次吸血
- **磁吸 × 经验加成**：磁吸觉醒吸取的经验球走原版拾取流程，经验加成照常生效
