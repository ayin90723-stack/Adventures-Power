## 总体架构

### 三层实现模型

30 种能力按对抗强度分布在三个实现层，**优先使用高层，仅在高层无法覆盖时才下沉**：

| 层 | 手段 | 特点 | 典型能力 |
|----|------|------|----------|
| **事件层** | Forge 事件（`LivingHurtEvent`、`PlayerTickEvent` 等） | 兼容性最好，其他模组可感知 | 灵巧、大地之力、伤害抗性 |
| **Mixin 层** | 字节码注入原版方法（`hurt`、`setHealth`、`canBeAffected` 等） | 拦截事件系统覆盖不到的路径 | 净魂、不朽装备、死亡抗拒 |
| **反射直写层** | `HealthUtil` 直接读写 `SynchedEntityData` 内部字段、实体追踪结构 | 对抗其他模组的 Mixin/ASM 拦截，"最终手段" | 影杀、真实血量、破敌之眼兜底 |

### 生效门禁模型

每个能力的效果执行前统一走 `AbilityGate` 门禁链：

```
服务端检查（isClientSide 直接 return）
  -> AbilityGate.isAbilityActive(player, id)   // 冒险者/觉醒身份 + 能力开关（P 键面板）
  -> 觉醒分支（isFullyUnlocked()）               // 仅数值/机制强化层，不是准入门禁
```

- **里程碑制**：所属里程碑解锁后即可使用，不要求觉醒。
- 攻击方能力（淬魂/影杀/禁疗/破敌觉醒等）监听 `receiveCanceled = true`，被其他模组取消伤害后仍正常执行；受伤方能力（伤害抗性）保留 `isCanceled()` 检查。
- 高频 Mixin 注入点（`getHealth`/`getAttribute`/`setHealth`）经 `ProgressCache` 按 tick 缓存 progress 引用，缓存的是引用而非门禁结果，开关/解锁/觉醒同 tick 即时生效。

### 数值成长公式

有成长的能力，数值随已解锁里程碑数（`count`）增长，`countAtUnlock` 为所属里程碑序号（`MilestoneRegistry` 动态填充）：

```
线性：value = BASE + PER × max(0, count - countAtUnlock)     // 灵巧、伤害抗性、加速等
步进：value = BASE + STEP × max(0, (count - countAtUnlock) / 2)  // 每 2 里程碑一档
固定：value = -1                                            // 解锁即完整
```

| 成长类型 | 能力（countAtUnlock） |
|----------|----------------------|
| **线性**（`LinearGrowthAbility`） | 灵巧(1)、大地之力(1)、不动如山(3)、加速(3)、无形之手(4)、磁吸(4)、经验加成(5)、嗜血(6)、伤害抗性(6)、禁疗之触(7)、坚韧之躯(7) |
| **步进**（`StepGrowthAbility`，divisor=2） | 休养生息(2)、鸿运当头(5) |
| **无成长**（`AbstractAbility`，value 固定 -1） | 虚空踏步(2)、灵魂绑定(3)、全视之眼(4)、不朽装备(5)、环境免疫(6)、死亡抗拒(7)、净魂(8)、满载而归(8)、翱翔(9)、淬魂之力(9)、破敌之眼(9)、恩赐永驻(9)、影杀(10)、真实血量(10)、拒绝篡改(10)、旅者之力(10) |
| **特殊** | 受击坚韧(8)：三档 5/8/12 层（里程碑 8/9/10），觉醒 +6 层 |

> 指令后门（`/ap unlock ability`）解锁的被禁用能力不经过里程碑，数值经 `AbilityGate.effectiveCount` 平移（解锁时 = 基础值，之后正常成长）。所有能力数值调用必须走 `effectiveCount` 或 `value`，禁止直接 `ability.value(count)`。

### 觉醒机制（第 11 阶段）

全部里程碑达成并持有「冒险的终点」后，全部 30 种能力获得强化：

- **数值强化**：× `AWAKEN_MULTIPLIER`（1.5）或独立配置项，部分带硬上限钳制
- **机制质变**：新增行为（御风冲刺、AOE 斩杀、威胁雷达等）

| 类型 | 能力 |
|------|------|
| **×1.5（钳制上限）** | 灵巧（钳 0.95）、大地之力（另 + 无视水中/空中惩罚）、不动如山（钳 100%）、无形之手、经验加成（×`awaken_xp_boost_mult`）、伤害抗性（钳 0.95）、加速（移速部分，另 + 疾跑推开） |
| **独立配置数值** | 休养生息（+5 HP）、磁吸（半径 ×1.5 + 吸经验球）、不朽装备（护甲 +2 / 武器 +25%）、鸿运当头（+2 等级）、禁疗之触（+ 易伤 ×1.2）、坚韧之躯（×1.5 向上取整）、受击坚韧（+6 层）、满载而归（取最大数量 + 每样 2 份）、翱翔（飞行速度 ×1.5）、淬魂之力（≤20% 斩杀 ×2.0）、拒绝篡改（30% 反弹）、旅者之力（审判范围 ×1.5 / 庇护可移动 30%） |
| **纯机制质变** | 虚空踏步（御风冲刺）、灵魂绑定（保经验）、全视之眼（威胁雷达）、环境免疫（免疫一切无实体来源伤害）、嗜血（过量吸血转护盾）、死亡抗拒（免费审判）、净魂（虚弱光环）、破敌之眼（禁无敌帧 3 秒）、恩赐永驻（正面无法驱散）、影杀（AOE 斩杀链）、真实血量（防秒杀底线 1 HP） |

## 共享基础设施

多能力共用的工具类，后文不再展开：

- **HealthUtil**：反射直写 `SynchedEntityData` 与实体追踪结构——读真实血量、直写回血/饱食度、饱和写入、实体抹除。模组内部降血（坚韧之躯裁剪等）必须包 `INTERNAL_HEALTH_WRITE` 标记，否则被拒绝篡改/死亡抗拒拦截、被真实血量反向修复
- **InvulClearUtil**：反射清除 Boss 自定义无敌字段（`invul`/`vulnerable` 命名模式）
- **FriendlyFireProtection**：超模进攻能力（淬魂/影杀/破敌/审判/嗜血）不对自身驯服生物生效
- **FortuneContext**：ThreadLocal 桥接"挖掘玩家上下文"到时运 Mixin 注入点
- **AbilityGate**：门禁断言 + 觉醒倍率计算 + `effectiveCount` 数值平移
- **AbilityIds**：30 个能力 ID 常量集中管理（typo 编译期可查）
- **ProgressCache**：高频 Mixin 注入点的 per-tick 门禁缓存（弱 key 防泄漏）
- **PiercingGazeUtil**：破敌之眼穿透结算公共工具（攻击者追溯/补 post/ActuallyHurt/兜底）
- **DamageUtil**：内部伤害源判定（`soul_strike`/`judgment`/`shadow_kill`，防递归重入）+ 伤害源工厂
- **ItemInventoryHelper**：背包/盔甲/副手/Curios 统一遍历
- **PersistentDataKeys / AdventureItemNbtUtil**：NBT key 常量集中管理 / 饰品 NBT 三层备份（恢复/同步/迁移/替换）
- **SyncUtil**：Capability 持久化 + 客户端同步（含里程碑注册表元数据，`/reload` 后版本号变化才重建）
- **ScoreboardUtil**：`adventure_power_unlock` 计分板，供命令方块/数据包查询全解锁状态
- **BuffExclusionManager**：恩赐永驻黑名单（persistentData 持久）

**网络层**（8 个包，C2S 全部带方向校验 + 服务端门禁）：

| 包 | 方向 | 用途 |
|----|------|------|
| `AdventureSyncPacket` / `AdventureSyncRequestPacket` | S2C / C2S | 同步 Capability（含注册表元数据）/ 客户端请求同步 |
| `DoubleJumpPacket` | C2S | 二段跳 |
| `AbilityTogglePacket` | C2S | 能力面板开关（服务端持久化） |
| `BuffTogglePacket` / `BuffBlacklistSyncPacket` | C2S / 双向 | 恩赐永驻黑名单开关 / 黑名单同步 |
| `ActiveSkillPacket` / `SkillSwitchPacket` | C2S | 释放主动技能 / 切换主动技能（服务端持久化并回同步） |

## 里程碑 1 · 初次夜冕

### 灵巧 `agility`

**效果**：受到任何伤害时有概率完全闪避（伤害归零，不触发后续减伤链）。闪避率 10% → 73% 随里程碑成长；觉醒 ×1.5，硬钳 ≤95% 防完全无敌。

**实现**：`LivingAttackEvent` 入口，通过门禁后按闪避率判定，命中 `setCanceled(true)` 在减伤前整体取消，生成 20 枚女巫粒子。

配置：`agility_base`(10) / `agility_per_milestone`(7) / `awaken_multiplier`(1.5) / `awaken_percent_cap`(0.95)

### 大地之力 `digging_power`

**效果**：挖掘速度 ×1.3 → ×1.75；觉醒约 ×2.625，且无视水中/空中挖掘惩罚。

**实现**：`PlayerEvent.BreakSpeed` 纯事件层，`setNewSpeed(原速 × 倍率)`；觉醒反向补偿原版 `/5` 惩罚（水中无水下速掘、未着地），叠加 ×1.5 倍率。

配置：`digging_power_base`(1.3) / `digging_power_per_milestone`(0.05) / `awaken_multiplier`(1.5)

## 里程碑 2 · 初尝败绩

### 虚空踏步 `void_step`

**效果**：空中可再次跳跃（二段跳），清空摔落距离。觉醒「御风」：疾跑时二段跳朝视角水平冲刺，松开疾跑为纯垂直跳。

**实现**（客户端预测 + 服务端权威，共用 `VoidStepMovement` 施力公式）：
- 客户端 `JumpInputHandler` 边沿检测 + 本地计数（空中 1 次，落地清零）做即时预测并发送 `DoubleJumpPacket`；服务端 `DoubleJumpHandler` 重校验门禁（不校 onGround），`AIR_JUMPED` 每空中周期限 1 次，落地清零
- 施力：Y 直接覆盖（`0.42 × JumpFactor + 跳跃提升`，整体 ×1.2）+ `fallDistance = 0`，保留当前水平动量；鞘翅滑翔/攀爬不触发
- 觉醒御风：疾跑时朝视角水平冲刺，冲量随当前移速加成（与加速能力联动）

配置：`void_step_power`(1.2) / `awaken_void_step_dash`(0.6)

### 休养生息 `rapid_recovery`

**效果**：脱战 5 秒后每 3 秒自动回血并回满饱食度，回量随里程碑成长；觉醒每周期额外 +5 HP。

**实现**：受击记录时间戳（被取消的伤害不计入脱战计时）；每 60t 检查脱战（100t 未受击）→ `HealthUtil.setAllHealthLikeRaw` **直写回血** + `restoreFoodData` 直写满饱食度。不用再生药水，避免被外部模组拦截/清除。

配置：`rapid_recovery_amplifier_base`(0) / `rapid_recovery_amplifier_step`(1) / `rapid_recovery_delay_ticks`(100) / `rapid_recovery_check_interval`(60) / `rapid_recovery_heal_per_amplifier`(1.0) / `awaken_rapid_recovery_bonus`(5)

## 里程碑 3 · 初次交易

### 灵魂绑定 `soul_bind`

**效果**：死亡时保留正面药水效果；觉醒时额外保留经验（不掉落）。

**实现**：死亡事件（@LOW，`isCanceled` 前置）只把正面效果序列化存入 persistentData；觉醒分支额外备份经验三字段（level/progress/total）并清零，死亡不再喷经验球。重生（Clone 死亡分支）读回并恢复，发 `ClientboundSetExperiencePacket` 同步经验。非死亡 Clone 防御性清理残留键。

配置：无（解锁即完整）

### 不动如山 `knockback_resist`

**效果**：击退抗性 30% → 79%；觉醒 ×1.5（硬上限 100%）。

**实现**：每 tick 对账直写 `KNOCKBACK_RESISTANCE` 基值（不用 modifier，无 UUID 冲突），仅与期望值偏差 >0.001 时写入；关闭/登出恢复写入前原值，不覆盖其他模组对基值的修改。

配置：`knockback_resist_base`(30) / `knockback_resist_per_milestone`(7) / `knockback_resist_hard_cap`(100.0) / `awaken_multiplier`(1.5)

### 加速 `swift`

**效果**：常驻移速加成（无图标），水下额外加速（海豚祝福），疾跑饱食消耗大幅降低；觉醒后疾跑碰撞推开敌对生物。

**实现**：移速经 `MOVEMENT_SPEED` 瞬态 modifier（`MULTIPLY_TOTAL`，bonus 变化才重写）；水下循环刷 `DOLPHINS_GRACE`；疾跑时负值补充 exhaustion 抵消原版消耗；觉醒每 5t 限频把半径内 `Monster` 推开（`setDeltaMovement` + `hurtMarked` 同步）。

配置：`swift_speed_base`(0.05) / `swift_speed_per_milestone`(0.02) / `swift_exhaustion_reduction`(0.8) / `swift_water_duration`(220) / `awaken_multiplier`(1.5) / `awaken_swift_push_radius`(3.0) / `awaken_swift_push_strength`(0.6)

## 里程碑 4 · 初探地底

### 全视之眼 `all_seeing`

**效果**：永久夜视（无图标无粒子，画面不闪烁）+ 消除下界/末地/水下雾气；觉醒后右下角威胁雷达（附近敌对生物 3D 方位 + 名称 + 距离）。

**实现**：夜视固定 400t 刷新（默认时长 2400t，剩余时间永远远离原版 200t 闪烁线）；客户端 `ViewportEvent.RenderFog` 把雾平面推远到 4096。觉醒雷达：客户端每 10t 扫描 24 格内 `Monster`，按 3D 距离排序取前 6，算方位词（本地化键）右下角右对齐渲染。

配置：`all_seeing_night_vision_duration`(2400) / `awaken_all_seeing_radius`(24) / `awaken_all_seeing_radar_max`(6) / `awaken_all_seeing_radar_scan_interval`(10)

### 无形之手 `extended_reach`

**效果**：方块交互距离 + 攻击距离同步 +1.0 → +2.2 格；觉醒 ×1.5。

**实现**：每 tick 对账直写 `ForgeMod.BLOCK_REACH` + `ENTITY_REACH` 两个属性基值，误差 >0.001 才写入；关闭/登出恢复原值（带残留判定，不覆盖其他模组修改）。

配置：`extended_reach_base`(1.0) / `extended_reach_per_milestone`(0.2) / `awaken_multiplier`(1.5)

### 磁吸 `magnet`

**效果**：自动吸取半径内掉落物至背包，半径随里程碑成长；觉醒范围扩大并吸取经验球。

**实现**：每 5t 限频扫描（降 getEntities 开销），对范围内 `ItemEntity` 按比例 lerp 朝玩家躯干中心拉取（穿墙）并清零惯性，近身调 `playerTouch` 触发原版拾取（尊重 pickupDelay）；`setPos` 后置 `hurtMarked` 同步位置。

配置：`magnet_radius_base`(5.0) / `magnet_radius_per_milestone`(0.5) / `magnet_pickup_radius`(1.5) / `magnet_scan_interval`(5) / `magnet_pull_factor`(0.3) / `awaken_magnet_radius_mult`(1.5) / `awaken_magnet_include_xp`(true)

## 里程碑 5 · 初次附魔

### 不朽装备 `undying_gear`

**效果**：所有装备耐久永不消耗；觉醒后每件护甲 +2 护甲值、主手武器 +25% 伤害。

**实现**：`LegacyHurtAndBreakMixin` 双注入点——`ItemStack.hurtAndBreak`（原版入口）与 `ItemStack.hurt`（Forge 独立入口，不经过前者）@HEAD 各 cancel + 耐久回满。门禁走主类静态方法。觉醒加成由属性 Handler 单独处理。

配置：`awaken_undying_armor_bonus`(2.0) / `awaken_undying_weapon_bonus`(0.25)

### 鸿运当头 `fortune_favor`

**效果**：时运与抢夺等级 +1 → +3（每 2 里程碑一档，在工具已有附魔上叠加）；觉醒额外 +2。

**实现**：抢夺走 `LootingLevelEvent` 纯事件层；时运无原版事件——`BlockEvent.BreakEvent` 时把玩家写入 `FortuneContext`（ThreadLocal），`EnchantmentHelper.getItemEnchantmentLevel` @RETURN 读上下文加 bonus（注入点无玩家参数，靠同调用链的 ThreadLocal 桥接）。

配置：`fortune_favor_bonus_base`(1) / `fortune_favor_bonus_step`(1) / `awaken_fortune_favor_bonus`(2)

### 经验加成 `xp_boost`

**效果**：拾取经验球时经验 ×1.25 → ×1.5；觉醒再 ×1.5。

**实现**：`PlayerXpEvent.PickupXp` 补差额方案——不 cancel、不反射，在原版拾取流程（含经验修补附魔/音效/粒子）之上额外 `giveExperiencePoints(base × (mult-1))`；事件被其他模组 cancel 时不补发。

配置：`xp_boost_base`(1.25) / `xp_boost_per_milestone`(0.05) / `awaken_xp_boost_mult`(1.5)

## 里程碑 6 · 炽热之门

### 环境免疫 `env_immunity`

**效果**：免疫火焰、冻结、雷击、摔落、溺水、仙人掌、凋零等环境伤害；觉醒后免疫**一切无实体来源的伤害**。

**实现**：`LivingAttackEvent` 在结算前取消——觉醒分支对 `getEntity()==null && getDirectEntity()==null` 直接取消；非觉醒按 `DamageTypeTags`（火/冰/雷/摔/溺水）+ `msgId` 字符串兜底（仙人掌、甜浆果、钟乳石、窒息、岩浆块、饥饿、凋零、干涸）；有实体来源的火焰弹火伤算战斗伤害不免疫。每 tick `clearFire()` 兜底直接烧火的模组。

配置：无

### 嗜血 `lifesteal`

**实现**：模组内最复杂的拦截体系，5 层纵深防御（4 Mixin + 1 事件 Handler），每层针对一类无敌实现：

| 层 | 位置 | 针对的无敌实现 |
|----|------|---------------|
| **Layer 0** | `Player.attack` 内 @Redirect `target.hurt()` | 完全重写 `hurt()` 的 Boss；血量比对确认实际扣血，未扣则手动补 post `LivingHurtEvent` + Accessor 直调 `actuallyHurt`（事件已发标记防重复补发导致监听器双倍结算） |

- 所有层带客户端跳过、内部源防重入、友伤保护

配置：`awaken_piercing_gaze_no_iframe_ticks`(60)

## 附录：能力联动关系

- **虚空踏步 × 加速**：御风冲刺冲量随当前移速加成，跑得快冲得远
- **淬魂之力 × 禁疗之触**：对禁疗标记中目标伤害 ×1.5
- **死亡抗拒 × 旅者之力**：觉醒触发时免费释放一次审判（不耗 CD、不占 GCD）
- **真实血量 × 拒绝篡改**：拒绝篡改拦「写入」（setHealth 拦截），真实血量修「已写入」（getHealth 时检测修复），共享 `HURT_DEPTH` 标记判定合法伤害
- **破敌之眼 × 影杀/嗜血等监听器**：Layer 0 放行时手动补 post `LivingHurtEvent`，被 ASM 改 hurt 的模组跳过原版事件时监听器仍能触发（事件已发标记防重复补发）
- **嗜血 × 伤害抗性**：嗜血 @LOW 基于减伤后最终金额吸血，顺序无歧义
- **影杀/淬魂/审判 × 嗜血**：内部伤害源（`soul_strike`/`judgment`/`shadow_kill`）不触发二次吸血
- **磁吸 × 经验加成**：磁吸觉醒吸取的经验球走原版拾取流程，经验加成照常生效
